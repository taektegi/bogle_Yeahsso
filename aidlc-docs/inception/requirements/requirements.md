### 핵심 요구사항 한눈에 보기
1. Google 계정으로 로그인하고, 내 친구·파일·대화는 나만 볼 수 있다.
2. 그림판 그림이나 종이 그림 사진을 올리면 OpenRouter를 통해 **배경 없는 캐릭터 PNG**를 만든다.
3. 이름(직접 입력)·성격 유형·좋아하는 것·말투(객관식)를 정하면 친구가 서버에 저장되고, **AI가 소개 문구를 만들어 준다.**
4. 보관함에서 친구를 보고, **영구 삭제**한다.
5. 친구의 집에서 **생성형 AI와 대화**한다. 대화는 저장되고 AI는 최근 대화를 기억한다. 22:00–06:00(한국 시간)에는 친구가 잔다.
6. 생성된 PNG의 **얼굴 좌표**를 한 번 분석해 저장한다. 앱은 몸 전체 애니메이션과 얼굴 덧그리기를 담당한다.
7. 돌봄 수치(기분·배부름·기운·친밀도), 레벨·추억, 인형 주문·결제는 **서버 범위에서 뺀다.**

### AI 호출 경로 (D-25, D-26)

- 앱 → FastAPI → OpenRouter → 선택한 모델 제공자 순서로 호출한다. 앱에 생성용 키를 넣지 않는다.
- 생성용 서버 키는 `OPENROUTER_API_KEY`다. OpenAI SDK를 쓰더라도 생성용 주소와 키는 OpenRouter 것으로 설정한다.
- 대화 안전성 검사는 별도 OpenAI Moderation 경로이며 `OPENAI_API_KEY`를 분리해 쓴다.
- 캐릭터 PNG 생성 직후 이미지 입력 모델로 얼굴 좌표를 한 번 분석한다. 형식·유한 수치·실제 PNG 크기·좌표 범위·부위 크기를 검증한 값만 저장한다.
- 얼굴 분석 실패·시간 초과·잘못된 응답은 생성 작업이나 친구 저장을 실패시키지 않고 `face: null`로 낮춘다.

## 5. 기능 요구사항

### FR-01. 인증과 데이터 소유권
- FR-01.1 앱은 Supabase Auth의 Google OAuth로 로그인한다. 처음 로그인하면 서버가 프로필을 자동으로 만든다(기본 닉네임 `그린고블린`).
- FR-01.2 앱을 다시 실행하면 저장된 세션을 복구한다. 세션이 만료되면 로그인 화면으로 돌아간다. 로그아웃할 수 있다.
- FR-01.3 FastAPI 서버는 모든 요청에서 Supabase가 발급한 액세스 토큰을 검증하고, **사용자 ID를 토큰에서만** 얻는다. 요청 body의 사용자 ID는 쓰지 않는다.
- FR-01.4 친구·업로드 파일·생성 작업·대화 메시지는 모두 소유자를 가진다. 다른 사용자의 리소스는 조회·변경·삭제·다운로드할 수 없다.
- FR-01.5 저장 파일은 비공개 버킷에 두고, 앱에는 만료되는 서명 URL로만 제공한다.

**수용 기준**
- 사용자 A의 토큰으로 B의 친구·작업·파일·메시지 ID를 요청하면 404 또는 403이 돌아온다.
- 앱과 서버를 다시 시작해도 같은 계정으로 로그인하면 친구·프로필·대화가 그대로 있다.

### FR-02. 프로필
- FR-02.1 닉네임: 공백을 제거한 뒤 1–12자. 비어 있으면 거부한다.
- FR-02.2 아바타: 내 친구 중 하나의 ID로 지정한다(현재의 에셋 경로 방식 대체). 지정한 친구가 삭제되면 기본 아바타로 바뀐다.
- FR-02.3 친구 알림·주문 알림 설정값(true/false)을 저장한다. 실제 푸시는 보내지 않는다.
- FR-02.4 마이페이지 집계로 보유 친구 수를 제공한다. 추억 합계는 삭제한다(D-14). 진행 중 주문은 앱의 mock을 유지한다(D-22).
- FR-02.5 수정은 허용된 필드만 부분 수정(PATCH)한다.

### FR-03. 그림·사진 업로드
- FR-03.1 입력 유형은 `drawing`(그림판)과 `photo`(카메라 촬영·사진 보관함)다.
- FR-03.2 그림판은 화면 확대와 상관없이 원본 캔버스를 PNG로 내보낸다. 사진은 카메라·사진 편집 화면이 만든 JPEG를 그대로 올린다.
- FR-03.3 서버는 실제 파일 형식(PNG/JPEG), 크기 상한, 해상도 상한을 검사한다. 통과한 파일만 `sourceAssetId`를 받는다.
- FR-03.4 업로드 파일은 소유자 경로(`{userId}/...`) 아래에 저장한다.

### FR-04. 친구 생성 작업 (OpenRouter 이미지)
- FR-04.1 앱은 `sourceAssetId`로 생성 작업을 요청한다. 같은 요청을 다시 보내면(같은 멱등 키) 같은 작업을 돌려준다.
- FR-04.2 서버는 원본 이미지를 OpenRouter를 통해 선택한 이미지 모델에 보내 **배경이 투명한 캐릭터 PNG 1장**을 만든다. 서버는 이 PNG에서 대표색(ARGB)을 뽑고 썸네일을 만든다.
- FR-04.3 작업 상태는 `queued → processing → succeeded | failed | cancelled`다. `succeeded`는 결과 파일을 실제로 읽을 수 있을 때만 반환한다.
- FR-04.4 실패하면 오류 코드를 준다. 예: OpenRouter 또는 모델 제공자 거부·정책 위반, 시간 초과, 입력 이미지 문제, 일시 오류. 일시 오류만 `retryable: true`다.
- FR-04.5 사용자는 작업을 취소할 수 있다. 취소와 완료가 동시에 일어나면 서버의 최종 상태를 반환하고, 앱은 취소한 시도의 늦은 결과로 화면을 넘기지 않는다.
- FR-04.6 앱의 5분 UI 시간 초과는 서버 실패와 같지 않다. 앱은 같은 작업 ID로 다시 조회할 수 있다.
- FR-04.7 재시도할 때는 실패 작업 재실행과 새 결과 생성을 구분한다.
- FR-04.8 생성 성공이 친구 저장으로 이어지지 않은 작업과 파일은 일정 기간 뒤 정리한다(기간은 24시간으로 결정 — OI-06).

**수용 기준**
- 서로 다른 두 그림에서 각각 다른 결과가 나오고, 각 원본과 결과가 친구 저장까지 섞이지 않고 이어진다.
- 생성이 실패하면 친구가 저장된 것으로 보이지 않는다.
- 중복 클릭, 취소, 앱이 백그라운드에 갔다가 돌아오는 경우에도 작업이 하나만 생긴다.

### FR-05. 초기 설정과 친구 저장
- FR-05.1 설정 단계는 **이름 → 성격 유형 → 좋아하는 것 → 말투** 순서다.

| 항목 | 입력 방식 | 규칙 |
|---|---|---|
| 이름 | 직접 입력(텍스트·음성 받아쓰기) | 공백 제거 후 1–12자. 글자 수는 사용자에게 보이는 글자(grapheme) 기준 |
| 성격 유형 | **객관식 단일 선택** | 서버가 관리하는 성격 유형 목록 중 하나 (목록은 기획에서 정함 — OI-01) |
| 좋아하는 것 | 객관식 다중 선택 | 1개 이상. 현재 선택지: 사과, 친구랑 놀기, 산책, 구름, 낮잠, 그림, 노래, 바다 |
| 말투 | 객관식 단일 선택 | `~지요!`, `해요체`, `반말` (표시명 `~지요!`, `다정하게`, `친근하게`) |

- FR-05.2 친구 생성 요청에는 `generationJobId`가 필요하다. 서버는 그 작업이 내 것이고 `succeeded` 상태인지 확인한다. 작업 하나로는 친구 하나만 만들 수 있다.
- FR-05.3 서버가 친구 ID를 발급한다. 친구는 원본 파일·캐릭터 아트·썸네일·대표색을 생성 결과에서 가져온다. 클라이언트가 보낸 이미지 경로·색은 쓰지 않는다.
- FR-05.4 친구를 저장한 뒤 서버는 설정값을 바탕으로 OpenRouter를 통해 **소개 문구(최대 70자)** 를 만든다. 실패해도 친구 저장은 성공으로 두고, 소개는 비워 둔다. 비어 있으면 앱이 기본 문구를 보여 준다.
- FR-05.5 앱은 서버가 돌려준 친구 객체를 이후 화면에 쓴다.
- FR-05.6 저장이 실패하면 입력값을 유지하고 다시 시도할 수 있다. 같은 요청을 다시 보내도 친구가 두 번 생기지 않는다.

### FR-06. 보관함 (목록·삭제)
- FR-06.1 내 친구 목록을 정해진 정렬 순서로 제공한다(정렬 기준은 OI-07). 데모 규모라 페이지네이션은 선택 사항이다.
- FR-06.2 친구 정보(이름·성격 유형·좋아하는 것·말투·소개 문구)는 수정할 수 없다(D-24). 서버에 친구 수정 API를 두지 않는다.
- FR-06.3 삭제는 즉시 영구 삭제다. 친구와 함께 대화 기록, 캐릭터 아트·원본 파일을 지운다. 아바타로 쓰던 친구면 프로필 아바타를 기본값으로 바꾼다.
- FR-06.4 앱의 "다시 데려오기" 기능은 제거한다.
- FR-06.5 삭제가 실패하면 성공으로 표시하지 않는다.

### FR-07. 찜 — 삭제됨 (D-24)
- 서버에 찜 데이터와 API를 두지 않는다. 다른 요구사항 번호를 유지하려고 번호만 남긴다.
- 앱에서 보관함·마이페이지의 하트와 `likedFriendIds`를 없앤다(FR-11.8).

### FR-08. 친구의 집 — 수면 상태
- FR-08.1 모든 친구는 한국 시간(Asia/Seoul) 22:00–06:00에 자고, 그 밖의 시간에는 깨어 있다.
- FR-08.2 수면 여부는 서버 시각으로 계산해 제공한다. 다음 전환 시각(`nextChangeAt`)도 함께 준다. 앱은 같은 규칙으로 화면을 바꿀 수 있지만, 판정은 서버가 기준이다.
- FR-08.3 자는 동안에는 대화를 보낼 수 없다. 서버도 이 요청을 거부한다.
- FR-08.4 간식 주기는 앱 안의 모션만 있고 서버를 호출하지 않는다. 자는 동안에는 앱이 간식을 막는다.
- FR-08.5 삭제되는 앱 기능: 상태 게이지(기분·배부름·기운·친밀도), 레벨·추억 표시, 쓰다듬기, 초대, 수면 일정 편집 다이얼로그.

### FR-09. 생성형 대화
- FR-09.1 앱은 `clientMessageId`와 본문으로 메시지를 보낸다. 같은 `clientMessageId`로 다시 보내면 새로 기록하거나 답을 새로 만들지 않고 이전 결과를 돌려준다.
- FR-09.2 입력 길이 상한을 둔다(값은 개발하면서 정함). 빈 메시지는 거부한다.
- FR-09.3 서버는 OpenAI Moderation으로 **사용자 입력**을 검사한다. 문제가 있으면 AI를 호출하지 않고 스크립트 대사로 답한다.
- FR-09.4 서버는 시스템 프롬프트에 캐릭터 설정(이름·성격 유형·좋아하는 것·말투·소개)과 아이 대상 안전 지침(나이에 맞는 말과 주제, 개인정보를 묻지 않기 등)을 넣고, **최근 N개 대화**를 문맥으로 붙여 OpenRouter 대화 모델을 호출한다(N은 OI-04).
- FR-09.5 서버는 AI 답변도 Moderation으로 검사한다. 문제가 있거나, AI 호출이 실패하거나 시간 초과되면 기존 스크립트 대사(`FriendTalk` 규칙)로 대체한다.
- FR-09.6 사용자 메시지와 친구의 답을 모두 저장한다. 메시지는 ID·친구 ID·발신자(user/assistant)·본문·생성 시각·답변 출처(`ai`/`script`)를 가진다.
- FR-09.7 친구의 집에 들어오면 이전 대화를 최신순으로 불러올 수 있다(커서 기반).
- FR-09.8 대화는 캐릭터 설정과 성장에 영향을 주지 않는다.
- FR-09.9 빠른 대화 버튼(‘오늘 뭐 했어?’, ‘뭘 좋아해?’, ‘같이 놀자!’, ‘사랑해!’)도 일반 메시지와 같은 경로로 보낸다.

**수용 기준**
- 다른 친구의 대화가 섞이지 않는다.
- 다시 보내도 메시지와 답이 한 번만 기록된다.
- OpenRouter·모델 제공자 또는 별도 Moderation API 장애 상황에서도 친구가 스크립트 대사로 답한다.
- 부적절한 입력에는 AI 답이 아니라 스크립트 대사로 답한다.

### FR-10. Flutter 모션용 얼굴 좌표
- FR-10.1 몸 전체 애니메이션은 Flutter가 캐릭터 PNG 한 장으로 처리한다. 백엔드는 GIF 모션 작업과 Meta Animated Drawings 파이프라인을 만들지 않는다(D-26).
- FR-10.2 서버는 캐릭터 PNG 생성 직후 OpenRouter의 이미지 입력 모델에 얼굴 좌표를 한 번 요청한다. 친구의 집 진입 때 다시 분석하지 않는다.
- FR-10.3 얼굴 지도는 version 1, `size`, `facing`, `head`, `eyes`, `mouth`, `cheeks`를 사용한다. 좌표는 생성 PNG의 픽셀 기준이다.
- FR-10.4 서버는 응답의 형식·유한 수치·실제 PNG 크기 일치·이미지 범위·양수 크기·부위 개수와 과도한 크기를 검증한다.
- FR-10.5 분석이 실패하거나 검증을 통과하지 못하면 생성·친구 저장은 성공하고 `face`만 `null`로 둔다. 앱은 몸 전체 애니메이션을 유지하고 얼굴 덧그리기만 생략한다.
- FR-10.6 검증된 얼굴 지도는 생성 작업과 친구에 저장하고, 생성 성공 응답과 친구 응답에 함께 반환한다.

### FR-11. Flutter 앱 연동 (D-04: 백엔드 담당이 작성)
- FR-11.1 Google 로그인 화면, 세션 복구, 로그아웃. 앱 시작 시 데모 친구·데모 주문을 넣지 않는다(주문 화면 mock은 유지).
- FR-11.2 `CharacterRepository`, `ProfileRepository`를 API 구현으로 바꾼다. 목적별 호출(생성·삭제·대화·프로필)로 나누고, 전체 객체 덮어쓰기(`saveFriend`, `saveProfile`)에 기대지 않는다.
- FR-11.3 그림판 PNG 내보내기, 사진 JPEG 전달(`_createFromPhoto`가 바이트를 넘기도록)과 업로드.
- FR-11.4 `CharacterGenerationJob`이 작업 ID·결과(`GenerationResult`)·실패 정보를 전달하도록 확장하고, `SetupFriendScreen`에 결과를 넘긴다.
- FR-11.5 원격 이미지 렌더링: 아트 표시·경계 측정·얼굴 위치 계산이 `Image.asset`, `SvgAssetLoader`, `rootBundle` 대신 네트워크 PNG도 처리하게 바꾼다. `isPhotographedArt()`의 경로 문자열 판정을 없앤다(생성 결과는 모두 투명 캐릭터).
- FR-11.6 설정 화면의 성격 입력을 객관식으로 바꾼다.
- FR-11.7 친구의 집에서 상태 게이지·레벨·쓰다듬기·초대·수면 일정 편집을 없애고, 대화를 서버 API로 바꾼다. 이전 대화를 불러온다.
- FR-11.8 보관함에서 "다시 데려오기", 친구 수정 화면, 찜 하트를 없앤다. 마이페이지의 찜 하트도 없앤다. 삭제 전 확인은 유지한다.
- FR-11.9 생성 결과와 친구 응답의 `face`를 저장해 눈꺼풀·입·볼 덧그리기에 사용한다. 서버 모션 클립 API는 호출하지 않는다.
