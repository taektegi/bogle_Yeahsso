# 보글 모션 기능 사용법

- 대상: 보글 iPad 앱 `친구의 집` 화면, 모션 서버 `motion_server/`
- 작성일: 2026-09-27
- 코드: GitHub `quasiaward/Bogle_doll_making_app`, 브랜치 `figma_design_develop` (커밋 `8843d8a`)

> **2026-09-28 변경:** 비눗방울 놀이(`놀아 주기`)와 `재우기` 버튼은 없어졌어요. 캐릭터가 스스로 하는 상시 모션, `초대하기`, 잠자는 시간, 새 간식 먹기 모션으로 바뀌었어요. 최신 내용은 [캐릭터 리그 규약](CHARACTER_RIG.md)을 보세요. 아래는 2026-09-27 기준 내용이에요.

## 한눈에 보기

친구의 집에서 아이가 친구와 몸으로 노는 기능이 두 층으로 되어 있어요.

| 층 | 무엇 | 언제 쓰이나 |
|---|---|---|
| 앱 안 움직임 | 간식 먹이기, 비눗방울 놀이, 늘였다 누르기·기울기 같은 탄성 동작 | 항상. 서버가 없어도 모든 친구에게 동작해요 |
| 모션 서버 클립 | 아이 그림을 실제로 움직이게 만든 짧은 영상(점프, 손 흔들기, 춤) | 서버를 켜고, 그림이 팔다리 있는 모양일 때만 |

모션 서버는 없어도 되는 선택 기능이에요. 서버가 꺼져 있거나 그림을 움직일 수 없으면 앱 안 움직임이 대신 나와요.

## 1. 앱에서 노는 법

### 간식 주기

1. 아래 `간식 주기`를 누르면 간식 쟁반(사과 · 도토리 · 쿠키 · 딸기)이 올라와요.
2. 간식을 손가락으로 끌어 친구에게 가져가요. 친구가 손가락 쪽으로 몸을 기울이며 기다려요. 간식을 톡 눌러도 바로 줄 수 있어요.
3. 친구가 두 입에 나눠 먹어요. 한 입마다 몸을 꾹 누르고, 부스러기가 튀고, 간식에 한 입 자국이 나요.
4. 배부름이 올라요. 좋아하는 것에 들어 있는 간식(하트 표시)은 기분이 더 오르고 특별한 대사가 나와요.
5. 배가 가득 차면 고개를 저으며 "이따가 먹을래"라고 해요.

### 놀아 주기 (보글보글 비눗방울 놀이)

1. `놀아 주기`를 누르면 15초짜리 비눗방울 놀이가 시작돼요.
2. 방 안을 톡톡 누르면 그 자리에서 비눗방울이 떠올라요.
3. 친구가 좌우로 달려가 점프해서 비눗방울을 터뜨려요. 위쪽에 터뜨린 개수와 남은 시간이 보여요.
4. 끝나면 터뜨린 개수만큼 기분이 오르고, 기운이 조금 줄고, 친구가 "N개나 터뜨렸어!" 하고 말해요.
5. 기운이 30 미만이면 놀이 대신 "조금 쉬고 싶어"라고 해요. `재우기`로 기운을 채울 수 있어요.

### 쓰다듬기

친구가 서 있는 자리 어디를 눌러도 쓰다듬어져요(그림이 작거나 납작해도 괜찮아요).

## 2. 모션 서버 켜기 (Mac)

처음 한 번만 설치해요. 20–30분쯤 걸리고, 모델 파일을 약 700MB 받아요.

```sh
cd ~/Bogle_app_service
motion_server/setup.sh
```

쓸 때마다 서버를 켜요.

```sh
motion_server/run.sh
```

켜지면 이런 줄이 나와요. 이 주소를 앱을 빌드할 때 넣어요.

```
*** Motion API: http://192.168.0.66:8000  (build the app with --dart-define=MOTION_SERVER=http://192.168.0.66:8000)
```

- 끌 때는 터미널에서 `Ctrl + C`.
- 잘 켜졌는지 확인: `curl http://127.0.0.1:8000/health` → `{"ok":true, ...}`

## 3. 앱을 서버와 연결해 빌드하기

| 어디서 | 명령 |
|---|---|
| 12.9" 시뮬레이터 | `flutter run -d 685DD2EC-841B-48E0-AD0F-ADD23751172E --dart-define=MOTION_SERVER=http://127.0.0.1:8000` |
| 유선 연결 iPad | `flutter run --release -d 00008103-001D78463C3B001E --dart-define=MOTION_SERVER=http://<Mac 주소>:8000` |

- 실제 iPad는 Mac과 **같은 Wi-Fi**에 있어야 하고, 주소는 `127.0.0.1`이 아니라 `run.sh`가 알려 준 Mac 주소예요.
- 처음 연결할 때 iPad가 "로컬 네트워크 접근" 허용을 물어요. 허용해야 해요.
- `--dart-define`을 빼고 빌드하면 앱은 네트워크를 전혀 쓰지 않고 앱 안 움직임만 써요.

## 4. 서버 클립이 나오는 때

친구의 집을 열면 앱이 뒤에서 조용히 친구 그림을 서버로 보내요(약 25초). 클립이 준비되면 그다음부터:

| 아이가 한 일 | 친구의 움직임 |
|---|---|
| 쓰다듬기 | 손 흔들기 (`wave`) |
| 좋아하는 간식 먹이기 | 점프 (`jump`) |
| 비눗방울을 하나 이상 터뜨리고 놀이가 끝남 | 춤 (`dance`) |

- 클립은 약 2.4초 동안 친구 자리에서 재생되고, 다시 원래 그림으로 돌아와요.
- 같은 그림은 서버에 저장돼 있어서 두 번째부터는 바로 나와요.
- 클립을 다 받기 전이거나, 동작 줄이기 설정이 켜져 있으면 앱 안 움직임이 나와요.

## 5. 움직일 수 있는 그림, 없는 그림

모델이 "팔다리가 있는 사람 모양 그림, 무늬 없는 종이"를 기준으로 학습돼 있어요. 서버가 먼저 검사해서, 안 되는 그림은 이상한 영상을 만드는 대신 이유와 함께 거절해요.

| 결과 | 뜻 | 예 |
|---|---|---|
| `ready` | 움직일 수 있어요 | 팔다리가 있는 사람·졸라맨 그림, Meta 예시 그림 |
| `not_humanoid` | 어깨 → 엉덩이 → 무릎 → 발 순서를 못 찾음 | 뭉글이(동그란 몸), 뚜치(네발 고슴도치) |
| `background` | 줄 노트 같은 종이 무늬가 캐릭터에 섞임 | 네모린(줄 공책에 그린 기린) |
| `no_figure` | 그림에서 캐릭터를 못 찾음 | 빈 종이, 너무 흐린 사진 |

지금 앱의 데모 친구 셋(뭉글이, 뚜치, 네모린)은 모두 거절돼서 앱 안 움직임을 써요. 잘 되는 그림을 받으려면:

- 흰 종이에 그리기 (줄 노트, 모눈 노트 피하기)
- 팔과 다리가 몸에서 떨어져 보이게 그리기
- 사진은 그림만 꽉 차게, 그림자 없이 찍기

## 6. 알아둘 점과 다음 단계

- **아직 새 친구 그림이 서버로 가지 않아요.** 지금은 앱에서 새로 만든 친구도 임시 그림(뭉글이)을 써요. 아이가 그린 실제 그림을 친구와 함께 저장하는 작업이 되어야 새 친구 클립이 생겨요.
- **개인정보**: 서버로 간 그림은 Mac의 `motion_server/data/jobs/`에 남아요(깃에는 올라가지 않음). 실제 서비스라면 보호자 동의와 보관 기간 정책이 필요해요. 사진에 아이 이름이나 얼굴이 찍힐 수 있어요.
- **속도**: 그림 하나에 약 25초(M4 Pro, GPU 없이). 친구가 생길 때 로딩 화면 동안 미리 만들어 두면 기다림이 가려져요.
- **입 모양 씹기는 없어요.** 모델은 몸 전체를 움직이는 방식이라, 먹는 느낌은 앱 쪽 연출(한 입씩 사라지는 간식, 몸 누르기)로 내요.

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `run.sh`에서 TorchServe가 안 켜짐 | `motion_server/data/torchserve.log` 확인. 설치가 덜 됐으면 `setup.sh` 다시 실행 |
| `/health`가 `"ok":false` | 모델 두 개가 다 올라올 때까지 20–30초 기다렸다가 다시 확인 |
| iPad에서 클립이 안 나옴 | 같은 Wi-Fi인지, 빌드 주소가 Mac 주소인지, iPad에서 로컬 네트워크를 허용했는지. 그리고 그 친구 그림이 `ready`인지 |
| 어떤 그림이 왜 거절됐는지 궁금함 | `curl http://127.0.0.1:8000/motions/<id>`의 `reason`, 또는 `motion_server/data/jobs/<id>/joint_overlay.png`(찾은 관절 표시) |
| `git fetch`가 대소문자 오류로 실패 | GitHub에서 `Figma_design_develop`(대문자 F) 브랜치 삭제 |

## 서버 API (개발용)

| 요청 | 응답 |
|---|---|
| `POST /motions` (멀티파트 `image`) | `{id, status}`. 같은 그림은 늘 같은 id |
| `GET /motions/{id}` | `{status, clips: {jump, wave, dance: {url, box}}, reason}` |
| `GET /motions/{id}/{clip}.gif` | 투명 배경 GIF, 720px, 약 2초, 약 1.7MB |
| `GET /health` | `{ok, models}` |

`status`는 `queued` → `working` → `ready` / `unsupported` / `failed` 순서예요. `box`는 클립 안에서 캐릭터가 움직이는 범위(비율)라서, 앱이 이걸로 친구를 방 바닥에 맞춰 세워요.
