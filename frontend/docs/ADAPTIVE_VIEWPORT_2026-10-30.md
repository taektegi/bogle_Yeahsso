# iPad 화면 비율 자동 적응 — 2026-10-30

작업 브랜치: `release`. 기존 가로 화면 정책과 12.9인치 디자인을 유지한다.
기기 모델명이나 물리 해상도 대신 실제 Flutter 논리 화면 크기, 안전 영역,
키보드가 차지하는 공간과 시스템 글자 크기로 자동 배치한다. 사용자 설정은 필요 없다.

## 구현

- `BogleViewport`: 기존 1194×834 디자인 좌표계, 공통 여백, 큰 글자 헤더 높이,
  좁은 공간의 패널/스크롤 전환 기준을 한곳에서 관리한다.
- 공통 헤더와 홈 헤더: 정상 iPad 크기의 원래 위치·로고·아이콘 크기는 유지.
  제목이 우측 아이콘 영역을 침범하지 않게 제한하고, 640pt 미만에서는 두 줄로 배치한다.
  스케치북의 좁은 헤더는 ‘그리기 / 사진’으로 표시하며 기존 기능과 선택 상태는 유지한다.
- `BoglePanelFlow`: 넓으면 기존 두 칸 배치, 좁거나 큰 글자로 공간이 부족하면
  위아래 패널과 스크롤/스크롤바로 전환한다. 주문 친구 선택·옵션·결제 화면에 적용.
  GlobalKey로 재배치 시 입력 요소의 State와 포커스를 유지한다.
- 캐릭터 설정: 기본 화면은 기존 배치. 좁거나 짧은 공간 및 큰 글자에서는
  질문·입력·선택지와 인사 화면을 스크롤할 수 있게 한다. 터치 영역은 최소 48pt 확보.
- 보관함: 짧은 화면에서 고정 최소 카드 높이로 공간을 넘지 않도록 제한한다.
  마이페이지는 작은 창에서 좌우 여백을 유연하게 조정한다.
- 스케치북: 원본 종이 크기를 초안에 저장하고 `PaperViewport`로 균일하게 맞춘다.
  표시 영역이 바뀌어도 벡터 좌표·생성 식별자·undo/redo·PNG 크기/내용은 바뀌지 않는다.
  새 입력 좌표, 확대/이동, 지우개/Pencil hover 표시도 표시 배율을 반영한다.
  여백은 크림색으로 구별한다. 기존 크기 없는 초안은 undo/redo에 있는 그림까지
  포함하는 종이 크기로 이전하고, 생성 완료 시 원래 정책대로 새 종이로 시작한다.
- 카메라/사진 검토 및 캐릭터 집은 기존 비율 유지 로직을 재사용하고 회귀 검증한다.
  `UIRequiresFullScreen`과 지원 방향은 변경하지 않았다. 좁은 창 검증은 레이아웃의
  강건성 검증이며 iPadOS 멀티태스킹 지원을 새로 켠 것은 아니다.

## 검증

- 논리 화면 12종: 1024×768, 1080×810, 1133×744, 1180×820, 1194×834,
  1210×834, 1366×1024, 1376×1032, 1600×1200, 1024×600, 744×600, 600×600.
- 홈·보관함·스케치북·집·주문·마이페이지의 기본 배치와 일부 화면의 2배 글자:
  총 96개 화면 조합. 안전 영역도 포함해 overflow 예외 없이 통과.
- 실제 앱 폰트로 좁은 주문 흐름, 옵션 유지, 촬영·검토·재촬영 확인.
  캐릭터 설정은 이름부터 인사까지 큰 글자 상태로 진행하고 8가지 말투 조합 검증.
- 실시간 크기 변경 후 그림/undo/PNG 바이트 동일성, 새 입력의 원본 좌표 정확성,
  입력 State·포커스 유지, 기존 초안 이전 및 생성 후 초기화 검증.
- 전후 캡처 및 기존 위치/크기 테스트로 1366×1024 기본 배치 유지 확인.
  전체 순서 캡처에서 홈·보관함·주문·마이페이지 픽셀 동일도 확인했으나,
  개별 테스트만 캡처하면 비동기 이미지 로딩 시점에 따라 이미지가 아직 없는 프레임이
  찍힐 수 있다. 픽셀 비교만을 근거로 삼지 않고 배치 테스트와 실기기 화면도 확인했다.
  캡처는 로컬 `artifacts/adaptive-viewports/`에 있으며 Git에는 포함하지 않는다.
- `flutter analyze`: 오류 없음.
- `flutter test --reporter expanded --dart-define=CAPTURE_SPEECH_DESIGN=true`:
  **560 passed, 3 skipped**. skip은 기존 테스트의 조건부 항목이다.
- 이전 대화 복귀 버튼 변경 후 남아 있던 테스트의 옛 ‘대화 닫기’ tooltip 탐색을
  실제 `house-chat-return` key로 수정했다. 동작 검증은 그대로 유지했다.

화면 크기 조합 검증은 widget 환경에서 수행했다. 모든 크기의 물리 iPad를

- 기존 앱 데이터 6개 파일을 설치 전에 별도 백업했다. 앱 삭제/데이터 초기화 없이 업데이트.

  최종 앱 실행 성공(PID 1099) 및 실행 프로세스를 확인했다.
