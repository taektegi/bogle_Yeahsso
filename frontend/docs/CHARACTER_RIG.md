# 캐릭터 리그 규약 — AI가 만든 캐릭터도 스스로 움직이게

- 대상: 친구의 집 캐릭터 모션 (`lib/src/screens/house/figure_motion.dart`, `figure_rig.dart`)
- 작성일: 2026-09-28

## 문제

집 안의 움직임은 두 층이에요.

| 층 | 예 | 필요한 것 |
|---|---|---|
| 몸 전체 | 폴짝 뛰기, 빙그르르, 흔들 춤, 갸우뚱, 두리번, 에취, 딸꾹, 부르르, 기지개, 꾸벅 졸기, 몸으로 인사, 간식 먹을 때 몸 들썩임 | 그림 한 장이면 충분 |
| 몸의 부분 | 한쪽 팔 흔들기, 눈 깜빡임·찡긋·두리번, 입 벌리고 오물오물, 볼 빵빵 | 팔·눈·입·볼이 **따로 떨어진 그림**, 또는 PNG라면 **얼굴 위치** |

처음에는 뭉글이 그림을 손으로 잘라 둔 파일(`rig_*.svg`)과 코드에 적어 둔 좌표로만 부분 모션이 나왔어요. 그래서 AI가 새로 만든 캐릭터는 몸 전체 모션만 할 수 있었고, 팔 인사, 눈 깜빡임, 먹는 입 모양은 없었어요.

## 해결

1. **그림이 스스로 부위를 알려 줘요.** 캐릭터 SVG 안에서 부위 그룹에 약속한 `id`를 붙여요. 앱이 그림을 읽을 때 이 이름으로 부위를 찾아 레이어로 나눠요. 코드에 캐릭터별 좌표를 적을 필요가 없어요.
2. **위치와 회전축은 앱이 계산해요.** 부위마다 실제로 그려진 영역을 렌더링해서 재요. 팔 회전축은 몸 쪽 아래 모서리, 눈은 가운데 선, 입은 윗입술로 정해요. 필요하면 그림에서 직접 지정할 수도 있어요.
3. **PNG는 얼굴 지도로 해결해요.** 아래 "PNG 캐릭터" 절을 참고하세요.
4. **빠진 부위가 있어도 움직여요.** 팔이 없으면 인사를 몸 전체로 하고, 입이 없으면 먹을 때 몸만 들썩여요. 아무 정보가 없는 그림(사진 포함)도 몸 전체 모션은 모두 해요.

그래서 **생성 결과가 아래 규약만 지키면, 새로 만들어진 캐릭터도 설치나 코드 수정 없이 모든 모션을 자동으로 갖게 돼요.** 뭉글이의 두 그림(`character_card.svg`, `character_friend.svg`)도 이 규약으로 바꿨고, 미리 잘라 둔 파일은 지웠어요.

## 생성 결과 규약 (캐릭터 생성 AI → 앱)

- 형식: SVG, `viewBox` 필수. 캐릭터는 정면 또는 옆모습으로, 배경이 없어야 해요.
- 부위 그룹 `id` (모두 선택 사항):

| id | 부위 | 움직임 | 기준점 (지정하지 않으면 자동) |
|---|---|---|---|
| `bogle-eyes` | 두 눈 | 깜빡임, 먹을 때 찡긋, 놀라면 커짐, 잘 때 감김 | 눈 영역의 가운데 |
| `bogle-mouth` | 입 | "아~" 벌리기, 오물오물 씹기, 꿀꺽 후 "냠" | 윗입술(영역 위쪽 가운데) |
| `bogle-cheeks` | 볼 | 씹을 때 빵빵 | 볼 영역의 가운데 |
| `bogle-arm-left` | 화면 왼쪽 팔 | 인사, 만세, 흔들 춤, 잘 때 늘어짐 | 팔 영역의 오른쪽 아래(몸 쪽) |
| `bogle-arm-right` | 화면 오른쪽 팔 | 〃 | 팔 영역의 왼쪽 아래(몸 쪽) |

- 팔의 어깨 위치를 정확히 주려면 `data-bogle-pivot="x y"`를 붙여요(`viewBox` 좌표).
  예: `<g id="bogle-arm-right" data-bogle-pivot="166.4 90">`
- 부위 그룹 밖의 모든 것은 "몸"으로 그려요. 부위는 원래 그림에서 앞뒤 순서 그대로 몸 위에 겹쳐져요.
- 옆모습이면 `<svg>`에 `data-bogle-facing="left"`(또는 `"right"`)를 붙여요.
- Figma에서 레이어 이름을 위 `id`로 지으면 SVG로 내보낼 때 그대로 `id`가 돼요.

## PNG 캐릭터: 얼굴 지도 (`<이름>.face.json`)

그림 생성 모델은 팔·눈·입을 따로 떨어진 투명 레이어로 **안정적으로 내주지 못해요.** 한 장의 그림을 잘 만드는 게 목적이라서, 부위를 잘라 달라고 하면 모양이 어긋나거나 빈틈이 생기기 쉬워요.

그래서 PNG는 레이어 대신 **좌표만** 받고, 움직이는 얼굴은 앱이 그림 위에 직접 그려요.

- **눈:** 주변 피부색으로 칠한 눈꺼풀이 내려와 깜빡이고, 찡긋하고, 잘 때 감겨요. 피부색은 앱이 그림에서 직접 읽어요.
- **입:** "아~" 하고 벌어지고, 오물오물 씹는 선이 움직이고, "냠" 할 때 다시 벌어져요.
- **볼:** 씹을 때 발그레해져요.
- **평소:** 아무것도 그리지 않아서 원래 그림 그대로예요.

좌표는 **그림을 보고 위치를 말해 주는 모델**(이미지 입력이 되는 언어 모델)에게 JSON으로 받는 게 쉽고 정확해요. 생성 직후 한 번만 물어보면 돼요.

```json
{
  "version": 1,
  "size": [1207, 2250],
  "facing": "left",
  "head": [0, 280, 470, 305],
  "eyes": [[335, 365, 35]],
  "mouth": [78, 545, 100, 32],
  "cheeks": [[195, 482, 38]]
}
```

| 키 | 뜻 (모두 그림의 픽셀 좌표) |
|---|---|
| `size` | 그림의 가로·세로 |
| `facing` | `"left"`, `"right"`, `"front"` — 캐릭터가 보는 방향 |
| `head` | 머리 상자 `[x, y, 너비, 높이]` (뿔·귀는 빼고) |
| `eyes` | 눈마다 `[중심x, 중심y, 반지름]` (보이는 눈만) |
| `mouth` | 입 `[중심x, 중심y, 너비, 높이]` (입이 안 그려져 있으면 입이 있을 자리) |
| `cheeks` | 볼마다 `[중심x, 중심y, 반지름]` |

- **잘못된 좌표 거르기:** 앱이 그림과 대조해서, 그림 밖(투명한 곳)을 가리키는 눈은 버려요. 빠지거나 틀린 항목은 그 부위만 움직이지 않아요.
- **적용된 캐릭터:** 지금 캐릭터 중 네모린(`nemorin.face.json`)과 뚜치(`dduchi.face.json`)의 얼굴 지도를 제가 그림을 보고 직접 재서 넣었어요. 뭉글이는 SVG 부위 이름을 써요.

### 좌표를 묻는 프롬프트 (생성 단계에 추가)

생성된 캐릭터 이미지와 함께, 구조화 출력(JSON 스키마)으로 요청해요.

```text
이 이미지는 아이의 그림으로 만든 캐릭터 한 명이에요 (배경 투명, 가로 {W}px × 세로 {H}px).
애니메이션을 위해 얼굴 위치를 픽셀 좌표로 알려 주세요. 원점은 왼쪽 위예요.

- facing: 캐릭터 얼굴이 향하는 쪽. 옆모습이면 코·주둥이 끝이 있는 쪽("left"/"right"), 정면이면 "front".
- head: 머리를 감싸는 상자 [x, y, 너비, 높이]. 뿔·귀·더듬이·머리카락 끝은 빼고 얼굴이 있는 부분만.
- eyes: 보이는 눈마다 [중심x, 중심y, 반지름]. 눈동자와 흰자를 합친 크기. 옆모습이면 한 개.
- mouth: 입의 [중심x, 중심y, 너비, 높이]. 입이 그려져 있지 않으면, 이 동물이나 캐릭터의 입이 있을 자리(옆모습은 주둥이 끝 아래쪽).
- cheeks: 볼마다 [중심x, 중심y, 반지름]. 눈과 입 사이, 눈 아래쪽.

모르는 항목은 빼고, 추측한 값은 이미지 안의 캐릭터 몸 위에 오도록 해 주세요.
JSON만 답해 주세요: {"version":1,"size":[W,H],"facing":...,"head":[...],"eyes":[[...]],"mouth":[...],"cheeks":[[...]]}
```

SVG로 생성한다면 같은 단계에서 "눈 그룹의 id는 `bogle-eyes`, 입은 `bogle-mouth` …"처럼 위 규약대로 부위 그룹 이름을 붙여 달라고 하면 돼요. SVG는 앱이 부위를 실제로 움직이므로 팔 인사까지 가능해요.

## 앞으로 할 일

- PNG 캐릭터의 팔은 여전히 몸 전체로 흔들어요. 팔을 움직이려면 팔 레이어가 따로 필요해요(SVG 생성 또는 별도 분리 단계).
