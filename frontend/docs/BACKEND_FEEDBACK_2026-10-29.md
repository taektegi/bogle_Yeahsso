# 개인 백엔드 피드백 연동

프론트엔드는 `release`, 백엔드는 `quasiaward/bogle_backend_try`만 대상으로 한다.
팀 저장소는 변경하지 않는다. 자세한 피드백별 판단과 서버 시나리오는 개인 백엔드의
`docs/FEEDBACK_VALIDATION_2026-10-29.md`에 기록한다.

## 앱 변경

- 성격 선택지는 기존 `friend_profile_choices.dart`의 네 문구가 기준이다.
  서버 코드를 앱에 강제하지 않는다.
- 기존 `sourceType` 계약을 유지한다. 백엔드가 drawing/photo별 프롬프트를 선택한다.
- 서버 생성 그림·썸네일은 PNG 시그니처와 실제 디코딩을 확인한 뒤 기기에 저장한다.
- 기기의 현재 UTC 오프셋을 API 요청마다 전송한다. 새 친구 저장에 앱 기본 수면 일정
  (21:00~07:00)을 명시해 서버 기본값과 달라지는 문제를 방지한다.
- 친구 저장의 요청 키를 생성 작업별로 고정한다. 응답 유실 후 같은 설정으로 재시도하거나
  앱을 다시 실행해도 같은 요청으로 복구한다.
- 생성 후 다운로드만 실패하면 같은 작업과 새 서명 URL로 다시 받는다. AI 생성을 다시 요청하지 않는다.
- 대화 전 편집 Outbox를 전송한다. 기본 친구·서버 연결 실패 때도 위험 신호에는 걱정 대사로 답한다.
- 사진 생성 화면의 돌아가기 버튼은 사진으로 돌아간다는 문구를 표시한다.
- 계약 스냅샷과 README의 백엔드 기준을 개인 저장소로 갱신한다.

## 검증

- `flutter analyze`: 통과.
- `flutter test`: **403개 통과**, 외부 연결 설정이 필요한 테스트 2개 생략.
- 모의 서비스 회귀 검증: 입력 구분, PNG 저장 검사, 시간대 변경, 다운로드 재시도 시
  중복 생성 방지, 앱 재실행 후 저장 키 유지, 로컬 대화의 위험 신호 분기.
- 별도 실행한 `test/e2e/backend_feedback_rehearsal_test.dart`: 실제 Dart HTTP 코드 →
  로컬 FastAPI → 실제 임시 PostgreSQL 통합 시나리오 통과.
- 실제 AI 호출은 사용자 선택에 따라 실행하지 않았다. 합성 PNG/JPEG와 모의 AI로
  처리 흐름을 검증했으므로 생성 이미지의 실제 품질 향상을 확정하지 않는다.
- 실제 `iPad (78)` (`00008103-001D78463C3B001E`)에 `lib/main.dart` 릴리스 빌드·
  업데이트 설치·프로세스 실행을 확인했다. 설치 전후 기기 보글 데이터 폴더를 별도로
  복사하고 기존 파일 해시가 동일함을 확인했다. 기존 앱 삭제·데이터 초기화는 하지 않았다.
  기기에는 서버 접속 설정 없는 일반 로컬 빌드를 설치했다.

## 실행과 데이터

일반 iPad 설치는 `lib/main.dart` 릴리스 빌드다. 기존 앱을 삭제하지 않고 업데이트한다.
`BOGLE_API_URL` 등이 없는 빌드는 로컬 모드이며 서버 연동 완료로 보고하지 않는다.
기존 기기 데이터는 통합 테스트에 사용하지 않는다. 테스트 데이터는 임시 폴더·DB에만 둔다.
