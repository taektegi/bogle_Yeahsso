# 사진 입력 품질과 실패 처리 개선 — FR-03/04

프론트 release / 개인 백엔드 main만 변경한다. 팀 백엔드와 운영 서버·DB는 변경하지 않는다.
AI 키가 없는 상태이므로 외부 유료 AI 호출은 하지 않는다.

## 사용자 흐름

촬영 또는 사진 선택 → 수동 회전·자르기·선명하게 → ‘대상 선택·사진 정리’ →
사물/종이 그림 선택 → 원본·처리 결과 비교 → 명시적 채택 → 친구 만들기.

- 사물: 사진에서 누른 위치를 실제 이미지 좌표로 환산해 Vision 전경 인스턴스를 선택한다.
  선택 위치를 표시하고 투명 여백을 포함한 단일 피사체 PNG를 만든다.
- 종이: Vision 사각형 검출과 Core Image 원근 보정으로 종이 바깥을 정리한다.
  흰 꽃잎·연한 선을 무조건 지우는 이진화나 생성형 재그리기는 하지 않는다.
- 자동 정리가 잘못되면 원본 유지, 수동 자르기, 촬영 원본 복원으로 돌아갈 수 있다.
  정리 결과는 사용자가 채택하기 전까지 원본/현재 편집 사진을 덮어쓰지 않는다.
- 비지원 기기·피사체 미검출·시간 초과에서도 원본으로 진행할 수 있다.
  연산은 background queue에서 직렬 처리하며 중복 네이티브 요청과 중복 제출을 차단한다.
- 최종 변환 중 편집을 잠그고 촬영/파일 읽기 오류는 재촬영 안내로 처리한다.
- 어두움·단색·흐림의 보수적 휴리스틱은 안내용이며 연한 그림을 강제 차단하지 않는다.
- 편집 전에 최대 2048px PNG로 정규화해 중간 이미지 메모리를 제한한다.
  사진 크기 40MiB 초과, 짧은 변 64px 미만, 극단적으로 가는 입력을 안내한다.
  업로드 공통 경로에서도 최소 해상도를 검사하고 실제 PNG/JPEG가 아닌 입력은 변환한다.
- API 주소가 없는 현재 로컬 모드는 정리 사진을 그대로 친구로 쓰는 미리보기임을 알린다.

## 개인 백엔드

PR https://github.com/quasiaward/bogle_backend_try/pull/5 / main 6da0dc0.
- photo의 완전 단색 입력은 유료 호출 전에 거절하되 투명 배경의 흰 피사체는 유지한다.
- 결과 PNG의 흰 배경 사각형과 크게 떨어진 복수 피사체를 보수적으로 거절한다.
  작은 장식·눈·발은 제외하고 drawing의 비정형 분리 구조에는 복수 피사체 검사를 적용하지 않는다.
- 이미 얼굴이 있는 그림/인형과 실제 사물의 얼굴 추가 지침을 나눴다.
  선택한 피사체를 우선하며 제거된 배경을 다시 만들지 않도록 했다.
- API 계약·DB·모델·medium·단일 생성/자동 유료 재시도 금지 정책은 유지한다.
- 원본 유사성, 붙어 있는 두 캐릭터, 모든 잘림·합성 오류까지 검출하는 의미 검사는 아니다.
  실제 AI 생성 결과의 시각 품질은 키 연결 후 별도 비교가 필요하다.

## 나중에 AI 키 연결하기

현재 서버는 OpenRouter 경유다. 생성할 키는 서버의 OPENROUTER_API_KEY에만 넣는다.
키를 앱·Git에 넣지 않는다. 그 뒤 원격 서버 환경과 앱의 기존 BOGLE_API_URL 및
Supabase 인증 설정을 연결한다. 키가 없는 원격 서버는 generation_unavailable을 반환한다.
전처리는 기기 내에서 동작하므로 AI 키 없이도 계속 사용할 수 있다.
