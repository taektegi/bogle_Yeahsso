# 말투 선택·계정 팝업과 프로필 확장

## 적용 내용

- `release`에서 캐릭터 말투를 네 가지 느낌(짧고 또렷하게 / 통통 튀게 / 동화 이야기처럼 / 로봇 친구처럼)과 편한 말·공손한 말로 분리했다. 놀이·간식·응원의 같은 상황 예문을 비교한다. 집의 실제 모의 대사와 개인 백엔드 AI 지침에도 반영한다.
- 기존 반말·해요체·~지요 및 자유 서술형 말투는 자동으로 덮어쓰지 않는다. 편집에서 새 말투를 고를 때만 바뀐다. 어려운 상황에서는 모든 방식이 차분하게 반응한다.
- 우측 상단 소식, 마이페이지 알림 설정·프로필·고객센터·정보 안내·주문 내역, 배송지·결제 수단 편집과 삭제 확인에 공통 `BogleDialog`를 적용했다. 크림색 바탕, 파란 제목 아이콘, 흰 카드, 둥근 버튼과 일관된 간격을 사용한다. 긴 본문은 스크롤하고 작업 버튼은 키보드 위에 둔다.
- 프로필에 한 줄 소개(60자), 좋아하는 활동(최대 3개), 포인트 색상(4종)을 추가했다. 소개·활동·색상을 마이페이지에 표시한다. 개인 연락처·생일·배송지·결제 정보는 추가하지 않았다.
- 친구 사진은 가로 목록으로 선택하고 투명 여백을 정규화한다. 저장 실패에는 재시도할 수 있으며 취소 시 변경하지 않는다. 예전 프로필은 빈 소개·활동과 하늘빛을 기본으로 읽는다.
- 개인 백엔드 `/v1/me`의 선택 필드와 마이그레이션을 추가하고 프론트 동기화 큐에 연결했다. 팀 백엔드는 수정하지 않았다.

## 검증

- Flutter 전체 테스트 448개 통과(기존 환경 의존 항목 2개와 선택적 캡처 테스트는 기본 실행에서 제외).
- 새 선택·저장·이전 값 유지, 말투 8조합의 실제 대사와 조사 치환, 프로필 취소·복원·활동 개수 제한을 확인했다.
- 작은 iPad 크기, 글자 2배 및 키보드가 열린 프로필 편집을 검사했다. 큰 글자에서 마이페이지 제목과 버튼이 겹치던 부분도 수정했다.
- `flutter analyze`: 문제 없음.
- 실제 앱 폰트·아이콘·캐릭터를 사용한 별도 렌더링 테스트 1개 통과. `flutter test test/account_visual_test.dart --dart-define=CAPTURE_ACCOUNT_UI=true`로 생성하며 `artifacts/account-visual/`의 팝업·편집·저장·말투 PNG를 직접 확인했다. 이 캡처는 실기기 캡처가 아니다.
- 개인 백엔드 실제 임시 PostgreSQL 전체 pytest 448개, Ruff 린트·포맷, GitHub CI 통과. [PR #4](https://github.com/quasiaward/bogle_backend_try/pull/4)를 main `2099840`에 머지했다. 로컬 main과 원격 main도 일치한다.
- 모의 AI로 검증했다. 실제 외부 AI 호출에 따른 자유 대화의 말투 구분·이미지 품질은 미검증이다.

## iPad 반영과 한계

실제 iPad Pro 12.9(5세대), `00008103-001D78463C3B001E`에 `lib/main.dart` 일반 릴리스(46.1MB)를 기존 앱 삭제 없이 업데이트 설치했다. 앱 저장 데이터 5개는 설치 전 백업과 SHA-256으로 일치한다.

앱 데이터 컨테이너 전체 복사는 처음 두 번 OS 보호 파일의 읽기 권한 때문에 실패했다. 이후 사용자가 잠금을 해제하고 `/tmp/bogle-account-full-unlocked`에 컨테이너 전체 백업을 완료했다. 저장 파일 5개는 기존 백업과 동일했다. 별도 QA 앱 식별자는 서명 프로파일 부재로 설치하지 못했으며 원래 식별자로 일반 릴리스를 다시 빌드·설치·실행했다.

전체 백업 후 메모리 저장소만 쓰는 실기기 자동 검증을 재시도했으나 테스트 빌드 설치 도중 기기 연결이 끊겨 중단됐다. `flutter drive`는 아직 실행하지 않았다. 사용자가 기기를 재연결한 뒤 미리 보관한 서명된 `lib/main.dart` 일반 릴리스를 다시 업데이트 설치했다. 실행 성공과 실제 Runner 프로세스를 확인했고, 복원 후 저장 파일 5개도 전체 백업과 SHA-256이 모두 일치했다. 최종 기기에는 일반 릴리스가 설치되어 있다.

첫 실행 요청은 기기 잠금으로 거절됐지만 최종 업데이트 후 실행에 성공했고 실제 Runner 프로세스도 확인했다. 실행 후 저장 파일 5개도 백업과 일치한다. 실기기 자동 터치·팝업 캡처 검증은 미완료이며, 시각 검수는 Flutter 렌더링으로 진행했다. 실기기용 `integration_test/account_speech_test.dart`는 메모리 저장소를 쓰도록 준비했다. 자동 테스트를 재실행할 때는 전체 백업과 `--keep-app-running` 조건을 지켜야 한다.

## 전체 검토 후 권장 순서

1. **서버 연동 배포**: main 머지와 운영 반영은 별개다. 개인 프로젝트의 새 DB 마이그레이션 두 개 → API 서버 → `BOGLE_API_URL`이 설정된 프론트 순서로 적용한다. 이번 일반 빌드는 기존 기본 설정대로 로컬 모드다. 이전 서버는 새 말투를 거절하거나 새 프로필 필드를 무시할 수 있다.
2. **동기화 상태 표시**: 현재 프로필은 기기에 먼저 저장하고 서버로 보낸다. 동기화 큐는 영구적인 4xx 오류를 제거하며 UI에는 상태가 드러나지 않는다. 기기 저장 완료 / 서버 동기화 대기 / 재시도 필요를 구분하면 시연과 장애 진단에 도움이 된다. 기존 설치에서 서버 변경분을 다시 받아오는 정책도 보완할 여지가 있다.
3. **알림의 역할 통일**: 현재 대부분의 상단 알림은 빈 소식함을, 마이페이지에서는 알림 설정을 연다. 소식함을 공통 진입점으로 만들고 설정은 소식함 안이나 하단 설정에서 여는 흐름이 일관된다. 실제 푸시는 아직 없고 설정값만 저장한다.
4. **실제 AI 품질 평가**: 모의 AI 테스트는 실패·저장·계약·대체 대사를 확인한다. 실제 배포 전에는 동일 질문으로 8개 말투를 비교하고, 그림/사진별 PNG·투명도·창문 배경·모션 실패 시 대체 동작을 실제 응답으로 확인하는 단계가 필요하다.
5. **고객센터·정보 문서**: FAQ는 사용할 수 있지만 1:1 문의와 정식 약관은 아직 준비 단계다. 심사 시에는 현재 구현 범위로 설명하고, 외부 공개로 범위가 바뀔 때 운영 내용을 확정하는 것이 좋다.
