# 개인 백엔드 최신 연동 보완

프론트 release / 개인 백엔드 main `b15354b`를 함께 검증했다. 백엔드 상세 분석·마이그레이션·시연 운영 기록은 [백엔드 연동 문서](https://github.com/quasiaward/bogle_backend_try/blob/main/docs/FRONTEND_INTEROP_2026-10-31.md)를 참고한다.

## 프론트 반영

- 422 fieldErrors로 식별된 거절 필드만 제외하고 나머지 PATCH를 재전송한다. 전송 중 새로 편집한 값은 이전 요청 오류로 제거하지 않는다. 거절·동기화 실패 안내를 앱에서 표시한다.
- 같은 사진/그림은 sourceType과 SHA-256으로 구분하여 업로드·멱등 키를 재사용한다. 해시 계산은 isolate에서 수행한다. 서버가 실패/취소를 확정하면 다음 시도는 새 키이고, 응답을 받지 못한 통신 실패·대기 시간 초과는 기존 키를 유지한다.
- POST 전에 요청 키·원본 ID를 보관하므로 작업 ID를 받기 전에 앱이 종료돼도 같은 요청을 이어 간다. 친구 저장 완료 후에는 해당 입력의 캐시를 해제해 새 만들기를 구분한다.
- 404/410 만료 작업의 이어 만들기 기록을 지운다. 일시적 503은 보관한다.
- 새 설치 복원 순서는 친구 그림 → 프로필이다. avatarCharacterId에 해당하는 친구 그림을 찾은 뒤 아바타를 연결한다. 아직 그림을 못 받았다면 프로필 복원을 완료한 것으로 저장하지 않는다.
- 서버 대화 한도·연결 실패로 기기 대사를 사용할 때 안내한다. 기기 대사는 서버 AI 기록으로 위장하지 않는다.
- 서버 OpenAPI 스냅샷을 동기화하고 프로필 확장 필드·window-view 계약 테스트를 추가했다. README 기준 브랜치를 개인 main으로 정정했다.

## 검증

- 백엔드 PostgreSQL 포함 458개 테스트 통과, ruff check/format 통과.
- 프론트 전체 618개 테스트 통과, 조건부 3개 건너뜀, flutter analyze 이상 없음.
- 실제 Dart HTTP → FastAPI → 임시 PostgreSQL 2차 검증 통과. 그림/사진 생성, 12자 이모지 닉네임·70자 소개·60자 bio의 DB 왕복, 이름 공백 보존, 422 부분 재전송, 새 설치 아바타 복원, 수면·대화, timeout/잘못된 PNG/거절 복구를 확인했다.
- iPad Pro 12.9 시뮬레이터 빌드·실행·화면 확인. iPad (78)에 일반 main.dart 릴리스 업데이트 설치·실행. 기존 저장 파일 21개가 업데이트 전후 바이트 동일했다.
- 실기기에서 사용자 데이터를 초기화하거나 손상시키지 않았다. 실제 AI·클라우드 배포·유료 호출과 실제 생성 품질은 검증 범위에 포함하지 않았다.

## 적용 시 주의

백엔드 배포 전 신규 `20261031000100_frontend_text_and_generation_requests.sql`을 대상 DB에 먼저 적용해야 한다. 이번에는 임시 DB에만 적용했다. 한도는 메모리 기반이므로 단일 인스턴스/워커 1개를 유지하며, 생성·대화의 멱등 기록은 DB에 저장됨을 구분한다. 시드 계정 청소는 운영자가 계정을 확인한 뒤 수행하며, 앱에 이미 내려받은 시드 친구도 별도로 정리해야 한다.
