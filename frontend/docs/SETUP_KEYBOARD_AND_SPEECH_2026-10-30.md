# 생성 이름 키보드 수정 및 말투 선택 정돈 — 2026-10-30

## 원인과 수정

이름 질문은 넓고 높은 화면에서 본문을 직접 렌더링하고, 키보드로 높이가 줄면 ScrollView+SizedBox로 감쌌다. 이때 EditableTextState가 dispose되면서 iOS 입력 연결과 포커스가 끊겼다. 키보드 크기 변경을 주입한 테스트에서 수정 전 다른 EditableTextState 인스턴스로 교체됨을 재현했다.

- 질문 영역은 항상 같은 ScrollView/SizedBox 구조를 유지한다. 공간에 따라 높이와 스크롤 가능 여부만 바꾼다. 기존 큰 화면의 크기·배치는 유지한다.
- `글자로 적기` 선택 후 새 입력창이 실제로 붙은 프레임 뒤에 포커스를 요청한다. 화면을 벗어났거나 다른 모드를 골랐다면 요청하지 않는다.
- 말투 생성 카드의 모든 아이콘과 마지막 버튼의 하트를 제거했다. 제목과 짧은 예문, 얇은 파란 테두리·선택 색상으로만 표현한다.
- 최종 버튼은 `친구로 만나기`로 정리했다. 기존 양진체·파란색을 쓰고 모서리를 12로 통일했다. 저장 중 진행 표시는 유지한다. 말투 저장 계약·저장 재시도·중복 저장 방지는 유지한다.

## 검증

- 생성·말투·오류 복구 테스트 18개 통과. iPad 크기에서 키보드 높이 360을 주입해 입력창 인스턴스·포커스·입력 연결이 유지되고, 키보드를 닫아도 같은 인스턴스임을 확인했다.
- 실제 글꼴로 기존 4가지 화면 크기(744 창의 글자 200% 포함) 말투 카드와 최종 버튼 캡처 확인. `artifacts/figma-speech-reference/`.
- Flutter analyze 통과.
- 유선 iPad (78)에 메모리 저장소만 쓰는 profile 통합 테스트를 설치했다. **TextInput 채널을 모의 등록하지 않고 iOS의 실제 viewInsets를 관측해 키보드 높이 498pt**를 확인했다. 키보드가 열린 뒤에도 같은 EditableTextState와 포커스가 유지됐다.
- 그 상태에서 실제 필드에 한글 IME 조합·완성 편집값을 전달해 `보글` 입력과 연결 유지를 검증했다. 물리적 키 터치를 자동화한 테스트는 아니다. Flutter 스크린샷에는 시스템 키보드 창이 포함되지 않으므로 키보드 표시는 네이티브 inset 측정으로 판정했다.
- 실기기 테스트 전 앱 컨테이너 전체를 `/tmp/setup-keyboard-ipad-full-before`에 백업했고, `flutter drive --keep-app-running`으로 실행했다. `artifacts/setup-keyboard-ipad/verification.json`에 검증 결과를 기록했다.
- 시뮬레이터는 `lib/main.dart` 일반 앱 빌드·실행·화면 확인 완료.
- 검증 뒤 `lib/main.dart` 일반 릴리스로 다시 업데이트·실행·화면 확인했다. native-assets 개발 팀 서명을 확인했으며, 원본 컨테이너 백업의 보글 저장 데이터 9개 파일과 복원 후 파일 내용이 모두 동일했다.
