# 주문·집 화면·스케치북 개선

작업 브랜치: `release`. 개인/팀 백엔드에는 수정 없음.

## 주문과 마이페이지

- 결제 API 호출 없이 600ms 동안 완료 처리를 시연하고 기기 주문 내역을 저장한다. 저장 성공 후에만 완료 화면을 연다. 중복 누르기 방지와 저장 실패 후 재시도를 유지한다.
- `paymentCompleted`, `simulatedPayment`를 주문에 기록한다. 외부 결제 영수증이나 승인번호를 만들지 않는다. 화면의 미리보기 안내와 자물쇠 아이콘을 제거했다. 실제 결제·제작·배송은 발생하지 않는다.
- 배송지/결제수단의 추가·수정·삭제·기본값 지정을 마이페이지와 주문 화면에서 공유한다. 기존 저장 형식을 읽으며 배송지에 안정된 ID를 부여한다. 기본 항목은 목록이 비어 있지 않으면 하나만 유지한다.
- 결제수단은 종류, 카드사/서비스/은행, 별칭, 뒤 4자리만 저장한다. 카드 전체 번호, CVC, 유효기간, 계좌 인증 정보는 입력받지 않는다.
- 주소록 변경이 과거 주문의 주소를 바꾸지 않는다. 주문 접수 상태인 주문은 마이페이지에서 별도로 배송지를 바꿀 수 있다.
- 저장 작업을 순서대로 처리하고 디스크 쓰기가 실패하면 메모리 상태도 복구한다.

배송지 흐름은 공개된 쇼핑몰 안내에서 공통으로 확인할 수 있는 주소록·기본 배송지·주문서 선택 방식을 적용했다. 앱 로그인 후의 모든 화면을 직접 비교하거나 기능별 이용 빈도를 정량 조사한 것은 아니다.

- [SSG 공식 배송지 FAQ](https://m.ssg.com/customer/faqSearchList.ssg?keyword=%EB%B0%B0%EC%86%A1%EC%A7%80): 주소록, 기본 배송지, 주문서 자동 적용과 접수 후 변경 흐름.
- [쿠팡 공개 사용 안내(제3자)](https://richdadsky.com/entry/쿠팡-배송지-관리에서-주소-추가·기본-설정·정리까지-한-번에), [무신사 공개 사용 안내(제3자)](https://nt2fqq.tistory.com/490): 보조 확인 자료. 무신사 공식 도움말은 접근되지 않아 공식 정책의 근거로 삼지 않았다.
- [카카오 우편번호 공식 가이드](https://postcode.map.kakao.com/guide): WKWebView에 `embed()`로 실제 도로명·지번·건물명 검색을 연결한다. 우편번호와 기본주소를 받아 상세주소 입력으로 이어진다. 네트워크 실패 시 재시도를 제공하며 기존 폼 내용은 유지한다. 수령인/전화번호는 검색 페이지로 전달하지 않는다.

## 집 화면

- `FriendFigure`에서 이미지의 실측 알파 영역과 가로세로 비율로 표시 크기를 정한다. 체감 면적의 기준을 맞추고 최대 폭·높이를 제한한다. 얼굴·입·간식·말풍선은 같은 원본 좌표계를 유지한다.
- 특정 캐릭터 이름별 배율을 하드코딩하지 않는다. 새 투명 PNG도 기존 `artLookOf`/`artCropOf` 측정을 사용한다. 긴 캐릭터는 종횡비를 보존하고, 측정 실패 시 기본 종횡비로 표시한다.
- 뭉글이의 기존 수중 배경은 유지한다. 뚜치: 숲, 네모린: 사바나, 뽀직뽀직: 우주, 민들레: 꽃밭, 귤이: 겨울 감귤 과수원으로 구분했다. 서버가 제공한 `friend.view`가 있으면 그것을 우선한다. 기존 기기의 저장된 기본 캐릭터에도 새 배경이 적용된다.
- 낮 이미지 5개는 built-in `image_gen`으로 제작했다. 저장 위치: `assets/figma/house_view_<id>_day.png`. 최종 프롬프트는 [window-background-prompts.json](window-background-prompts.json)에 보관한다. 밤에는 기존 파란색 딤 처리를 사용한다.

확인 결과 개인 백엔드 `server/app/image_provider.py`는 **캐릭터 PNG 생성**만 제공한다. 창밖 배경을 생성하는 엔드포인트는 없다. 프론트 `WindowViewPrompt`도 아직 실제 생성 호출에 연결되지 않은 규격이다. 이번 배경은 그 창문 구도 규격과 백엔드 그림책 화풍을 참고해 별도로 생성했다.

배경 생성 로직의 개선은 구현하지 않았다. 향후에는 이미지 분석으로 장소 후보를 정하고, 캐릭터 이름·외형·성격·좋아하는 것의 우선순위를 명확히 정하는 방식이 적절하다. 낮 이미지를 기준으로 밤을 편집 생성하고, 창틀 안전 영역·비율·문자/캐릭터 혼입·에셋 로딩 실패를 검증하는 방향을 제안한다. 서버 생성/저장/실패 재시도 계약부터 마련해야 한다.

## 스케치북

- Pencil 전용 모드에서 한 손가락으로 이동한다. 손가락 그리기 모드는 유지하고 손 도구로 이동을 선택한다. 두 손가락 확대에서 하나를 떼도 이동이 이어지며, Pencil을 대고 있는 동안 손바닥은 이동을 유발하지 않는다.
- 두 손가락 탐색으로 판정되면 먼저 시작된 부분/선 지우기를 취소한다.
- 초안, 원본 벡터 획, 실행 취소/재실행, 확대·위치, 종이, 색·굵기, Pencil 설정을 기기에 저장한다. 최근 실행 취소 기록은 80단계까지 보관한다. 저장 실패는 화면에 표시하고 재시도한다. 테스트에서는 메모리 저장소를 사용한다.
- 도구를 접어도 되돌리기·다시 실행·손 도구·설정은 남는다. 도구는 버튼을 축소하지 않고 제한된 높이에서 스크롤한다. 왼쪽 도구 배치, 빠른 색상, 약한 선 보정, 자동 도형 보정 안내를 추가했다.

## 주문 화면의 캐릭터 구분 디자인: 미적용 제안

주문 초상화·흰 원 배경·캐릭터 색상은 변경하지 않았다. Liquid Glass도 적용하지 않았다.

[Apple Materials HIG](https://developer.apple.com/design/human-interface-guidelines/materials)는 Liquid Glass를 조작·내비게이션 계층에 사용하고 콘텐츠 계층에는 사용하지 않도록 안내한다. [iOS 27 업데이트 안내](https://support.apple.com/en-gb/149076)의 투명도/가독성 개선이 흰 캐릭터와 흰 배경의 대비를 자동으로 보장하는 것은 아니다.

권장안은 실제 알파 영역의 밝기를 기준으로 고르는 차분한 바탕색, 아주 약한 실루엣 그림자, 원본 색상·투명도의 보존이다. 밝거나 어두운 캐릭터, 반투명 캐릭터를 함께 검증해야 한다. 흰색 픽셀을 일괄 제거하면 민들레의 꽃잎도 사라지므로 사용하면 안 된다. 불투명 배경이 들어온 PNG는 투명 PNG와 구분해 다뤄야 한다. Flutter의 단순 blur를 네이티브 Liquid Glass와 동일하다고 간주하지 않는다.

## 검증 기록

- 정적 분석: 문제 없음. 전체 단위/위젯 테스트: 423개 통과, 기존 2개 제외.
- iPad에서 실제 카카오 주소 검색 결과 1건 수신. 메모리 저장소로 배송지/결제수단 등록 → 모의 결제 → 주문 내역 표시 통과. 결과: `artifacts/order-demo/verification.json`.
- 집 화면의 크기 변경 후 기존 말풍선·간식 위치·히어로 전환 관련 검증 43개 통과.
- 통합 실기기 검증 진입점: `integration_test/release_details_test.dart`. 결과와 화면 캡처는 `artifacts/release-details/`에 저장한다.
- 통합 iPad 검증 5개 흐름 모두 통과: 실제 주소 검색, 주문 시연, 32종 터치·간식·대화·배웅, 스케치북 이동·복원, 6개 캐릭터 집 배경·크기. 뽀직뽀직/뭉글이의 그려진 영역 면적 비율은 1.2325로 확인했다. 화면 캡처로 배경과 스케치북 도구 배치도 점검했다.
- 설치 전에 `/tmp/bogle-order-full-backup-20261030`으로 앱 데이터 컨테이너 전체를 백업했다. 테스트 앱은 메모리 저장소만 사용하고 `flutter drive --keep-app-running`을 적용한다. 마지막에는 `lib/main.dart` 일반 릴리스 앱으로 업데이트한다.
- 최종 일반 릴리스 빌드(46.0MB)를 기존 앱 위에 설치하고 실행했다. 설치 후 캐릭터 JSON·그림 파일 2개가 전체 백업본과 SHA-256 기준 모두 일치했다. 테스트용 USB VM 전달 프로세스는 종료했다.
