# 중첩 화면에서 홈 복귀 시 집 노출 수정 — 2026-10-30

## 원인

집에서 마이페이지를 거쳐 생성 화면으로 이동한 뒤 홈을 누르면 일반 경로의 `popUntil(isFirst)`가 모든 화면을 동시에 pop했다. 일반 화면의 닫힘(220ms)이 끝나도 집 경로의 닫힘(800ms)이 남아 집이 잠깐 드러났다. 이 문제는 동일한 중첩 경로를 사용하는 다른 일반 화면에서도 발생할 수 있었다.

## 변경

- 공통 `bogleRoute`에 기존 집 경로가 사용하던 `HomeReturnRoute`를 적용했다. 홈 복귀 시 현재 화면을 덮개로 유지하고 아래 중간 경로를 제거한 뒤 기존 루트로 한 번만 닫힌다.
- 일반 페이지의 열림 260ms·닫힘 220ms와 슬라이드 형태는 유지한다. 일반 뒤로가기는 이전 화면으로 돌아간다. 집에서 직접 홈으로 돌아가는 특수 모션도 유지한다.
- 홈 화면을 새로 만들거나 스케치북·캐릭터 데이터를 초기화하지 않는다.
- 이미 dispose된 화면에서 지연된 홈 콜백이 들어오면 안전하게 무시한다.
- 앱의 일반 이동 경로는 공통 bogleRoute를 쓰는 것을 검색으로 확인했다. 외부 주소 검색용 MaterialPageRoute는 자체 뒤로가기만 사용하며 이번 변경 대상이 아니다.

## 검증

- 수정 전, 집 아래에 보관함·추가 화면을 두고 그 위에 프로필·스케치북 역할의 일반 경로를 쌓은 회귀 테스트에서 집이 남는 현상을 재현했다(모션 켜짐·줄이기 각각 실패).
- 수정 후 같은 테스트에서 전환 중 여러 시점에 집·보관함·프로필이 위젯 트리에서 제거됨을 확인했다. 반복·지연 홈 호출에도 루트는 유지된다.
- 집의 일반 뒤로가기 Hero 비행·원래 전환 시간·툴팁 활성 상태·모션 줄이기, 공통 헤더·생성 흐름 등 관련 테스트 22개 통과. Flutter analyze 통과.
- 시뮬레이터 일반 앱 빌드·실행·화면 확인 완료. 중간 프레임 회귀 검증은 실제 데이터 대신 테스트의 메모리 화면으로 수행했다.
- 유선 iPad (78)에 일반 릴리스 업데이트·실행·화면 캡처 완료. 개발 팀 서명과 업데이트 전후 앱 데이터 8개 파일의 내용이 모두 동일함을 확인했다.
