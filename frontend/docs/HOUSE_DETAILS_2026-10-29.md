# 캐릭터 집 상호작용 개선 (2026-10-29)

프론트엔드 `release` 브랜치에서 적용한다. 백엔드 API와 두 백엔드 저장소에는 변경이 없다.

## 사용 동작

- 초대하면 주인이 왼쪽으로 자리를 내주고 손님은 오른쪽에 선다. 손님은 주인의 90% 크기이며 같은 바닥선과 넓어진 러그를 사용한다. 배웅은 손 흔들기와 퇴장 후 주인의 중앙 복귀로 이어진다.
- 터치는 기존 기본 모션 중 32종을 섞어 하나씩 사용한다. 한 바퀴 안에서 중복하지 않고 다음 바퀴 첫 동작도 이전 터치와 다르게 고른다. 주인과 손님은 각각 덱을 가진다. 먹기·수면·입퇴장 중에는 해당 상황을 우선한다. 동작 줄이기 설정도 유지한다.
- 기존 손 흔들기 GIF가 터치 동작을 덮지 않게 했다. 성격에 따라 동작 강도와 쉬는 간격을 조절하고 일부 자율 행동에는 상대방의 짧은 후속 반응이 붙는다. 예약된 반응은 이후의 직접 터치·간식·대화를 덮지 않는다.
- 대화 답변은 방 안 말풍선으로 표시한다. 함께 있을 때 화자를 표시하고, 긴 답변은 눌러 다음 부분을 읽거나 길게 눌러 전문을 연다. 입력은 작은 크림색 받침에, 대화 이력은 별도 시트에 둔다. 답변 대기 표시와 중복 전송 방지, 키보드 공간 확보, 대화 중 자율 동작 억제를 포함한다.
- 간식을 누르면 둘이 나눠 먹는다. 특정 캐릭터에게 끌어 주면 그 캐릭터만 먹고, 둘 사이에 놓으면 함께 먹는다. 각각의 입 위치·좋아하는 간식·돌봄 수치를 사용하며 함께 다 먹은 경우 두 캐릭터에 추억을 기록한다. 손님 식사는 약간 늦게 시작한다.
- 손님을 쓰다듬으면 손님의 돌봄 기록이 저장된다. 입장·퇴장·식사 상태와 방문 식별자를 확인해 이전 방문의 늦은 반응이나 간식이 새 손님에게 적용되지 않도록 한다. 식사 중 도착한 채팅 답변은 식사가 끝나면 표시한다.

손님의 인사와 짧은 반응은 로컬 대사다. AI 대화는 기존 주인 캐릭터의 채팅 서비스를 사용한다. 이번 작업에서 다자간 AI 대화 API를 추가하지 않았다.

## 검증

- `flutter test`: 410개 통과, 기존 2개 제외.
- 터치 덱 4회 순환 중복 검사, 실제 위젯 32회 터치 검사.
- 간식 공유 및 개별 급식, 돌봄·추억 저장, 식사 중 배웅, 예약 반응 취소, 배웅 후 중앙 복귀 검사.
- 1024×768, 1194×834, 1366×1024에서 말풍선·캐릭터·입력창과 키보드 공간 검사.

- 스크린샷과 결과 JSON은 git에서 제외된 `artifacts/house-details/`에 저장한다. Flutter 렌더링 캡처이므로 iOS 키보드 자체는 캡처 이미지에서 빠질 수 있다.

## 실기기 검증 방법

기존 앱 데이터 컨테이너 전체를 먼저 백업한다. 테스트 앱은 기존 앱을 삭제하지 않고 업데이트 설치한다. `flutter drive`에는 항상 `--keep-app-running`을 지정한다.

일반 Flutter 기기 실행 경로가 디버거 연결을 기다려 직접 profile 앱 설치·실행 후 USB VM 서비스에 연결했다. USB 전달은 `iproxy`, 앱 실행은 `devicectl`, 검증은 `flutter drive --profile --keep-app-running --use-existing-app=... --no-dds`를 사용했다. VM 서비스 옵션은 테스트 프로세스에만 전달한다.

테스트 후 `flutter build ios --release --target lib/main.dart`로 일반 앱을 빌드해 업데이트 설치·실행하고, 저장된 캐릭터 JSON과 그림 파일을 백업본과 비교한다. 테스트용 연결 프로세스도 종료한다.

최종 반영: 일반 릴리스 빌드(35.7MB) 설치·실행과 Runner 프로세스 생존을 확인했다. 실행 전후 캐릭터 JSON 및 그림 2개 파일의 SHA-256이 전체 백업의 해당 파일과 모두 일치한다. 앱 삭제나 데이터 초기화 없이 업데이트했으며 테스트용 USB 전달 프로세스는 종료했다.
