# 서비스 안정성 추가 보완

프론트 release / 개인 백엔드 main 대상. 팀 저장소는 변경하지 않았다.

## 반영

- 잘못된 UTF-8은 readAsBytes 후 검사 안에서 디코딩한다. 바이트 손상은 정상 백업과 복구 안내로 넘어가며 실제 I/O 오류는 손상으로 오인해 초기화하지 않는다. 작은 문서는 직접 JSON 인코딩하고 큰 문서만 isolate로 옮긴다. 크기 추정은 이스케이프 확장을 보수적으로 고려하며 전체를 두 번 인코딩하지 않는다.
- Outbox도 구조 검증·백업·초기화 재시도 정책을 사용한다. 기기 저장 오류를 감추지 않으며 친구/프로필은 대기열을 먼저 보관하고 로컬 변경을 확정한다. 인증 실패를 영구 거절로 버리지 않는다.
- 거절 필드/값은 재실행 후에도 보관하고 마이페이지 ‘동기화 상태’에서 확인한다. 설정을 새로 수정하면 해당 실패가 해소된다. 동기화 시에는 대기 중/거절 상태 필드를 보호하고 다른 서버 설정을 반영한다. 서버에 마지막으로 수락된 값이 기준이며 사용자 선택형 다중 편집 충돌 UI는 범위 밖이다.
- 친구 이미지 한 개의 실패로 나머지 다운로드를 중단하지 않는다. 프로필 텍스트를 먼저 복원하고 누락된 아바타는 다음 동기화에서 재시도한다.
- 작업 ID 없이 요청 키만 남은 경우 홈 조회는 생성 POST를 보내지 않는다. ‘이어서 만들기’ 이후 결과를 구독할 때 시작하며 그 시점의 만료도 정리한다.
- 대화는 보이는 글자 200자 기준으로 전송/서버 검증을 통일한다. 서버 메시지 ID와 페이지 조회(최근 최대 500개)를 사용하며 ID로 중복을 판단한다. 실제 같은 문구의 반복을 보존하고, 서버 조회와 답변 수신이 겹친 경우 현재 낙관적 메시지의 중복을 막는다. ID가 없는 과거 로컬 기록은 임의로 지우거나 동일 메시지라고 단정하지 않는다.
- 작별 작업을 기기에 먼저 보관하고 되돌리기 시간 이후 그림/썸네일/얼굴 지도·대화/백업·창문 기록을 정리한다. 앱 종료 후에도 재개한다. 되돌린 친구·공유 그림과 늦게 도착한 응답의 기록 재생성도 보호한다. 정리된 대화의 메모리 캐시는 저장소별로 비운다.
- `_anchors`의 `그림#revision` 키를 포함해 파생 캐시도 제거한다. 받침 높이는 키보드 상태/폭/글자 배율별로 기록한다.
- PNG의 원래 입을 보존하고 추가 입을 덧그리지 않는다. 몸·고개·눈·볼·간식 동작과 SVG 입 레이어 모션은 유지한다. PNG 자체의 입을 동적으로 바꾸려면 향후 깨끗한 얼굴 바탕/마스크가 필요하며, 이번에는 임의의 피부색으로 입을 덮지 않는다.

## 검증

- 프론트 전체 629개 통과, 조건부 3개 건너뜀. 정적 분석 이상 없음.
- 백엔드 전체 461개 통과, ruff 통과. 마지막 연결 풀 정리 보강 후 스키마/정리 테스트 24개 재통과. GitHub CI 성공.
- 실제 Dart HTTP → FastAPI → 임시 PostgreSQL 연동 검증 통과. 외부 이미지 제공자는 모의 구현이다.
- 추가 테스트: UTF-8 바이트 손상/백업/원본 보관, 유료 POST 지연, 친구별 실패와 프로필 텍스트 복원, 거절 필드 재실행 보존·해소, 삭제 후 파일/백업 정리와 되돌리기 보호, ID 병합·수신 경합, 긴 이모지 경계 및 PNG 추가 입 픽셀 없음.
- iPad Pro 12.9 시뮬레이터 빌드·실행·화면 확인. iPad (78) 일반 main.dart 릴리스 설치 완료, 기존 파일 21개 바이트 동일. 현재 실기기는 잠겨 최종 실행 화면 확인은 잠금 해제를 기다린다.

## 배포 전

개인 백엔드의 신규 `20261031000200_chat_grapheme_limit.sql`이 추가됐다. `20261031000100_frontend_text_and_generation_requests.sql` 다음에 적용해야 한다. 서버 시작 전 필수 테이블과 대화 길이 제약을 검사하여 누락 시 필요한 파일명을 명시한다. 자동/운영 DB 마이그레이션이나 유료 AI 호출은 실행하지 않았다. 실제 생성 품질 검증은 키 등록 후 별도 진행한다. 메모리 기반 요청 한도는 계속 단일 인스턴스/워커 1개 운영이 전제다.
