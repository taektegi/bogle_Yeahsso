# 프로젝트 작업 규칙

## 현재 검증 대상 (2026-10-30 최신 사용자 지시)

- 맥북의 Xcode iPad Pro 12.9인치 시뮬레이터에서 빌드·실행·화면 확인을 유지한다.
- 앱 코드 수정 후에는 유선 연결된 실제 iPad에도 아래 규칙에 따라 리빌드·설치·실행 확인을 진행한다. 시뮬레이터 검증과 실기기 반영을 함께 수행한다.
- 시뮬레이터에서도 기존 앱과 데이터를 삭제하거나 초기화하지 않고 업데이트한다.

## 실제 아이패드 반영

- 사용자가 별도로 제외하지 않는 한, 앱 코드나 에셋을 수정하는 작업은 관련 검증 후 연결된 실제 아이패드에 리빌드·설치·실행 확인까지 수행한다. 시뮬레이터 업데이트만으로 완료하지 않는다.
- 설치 전 연결 기기를 확인하고 실제 아이패드를 대상으로 지정한다. 기기가 여러 대여서 대상이 불명확하면 사용자에게 확인한다.
- 일반적인 확인용 배포는 `lib/main.dart`를 진입점으로 릴리스 모드로 빌드해 케이블을 분리해도 실행할 수 있게 한다.
- 시뮬레이터에서 실기기로 전환한 뒤에는 포함된 native-assets 프레임워크도 개발 팀 서명인지 확인한다. `objective_c.framework` 등이 ad-hoc 서명으로 남아 설치가 거절되면 `flutter clean` 후 일반 릴리스를 다시 빌드한다.
- 기존 앱을 삭제하거나 앱 데이터를 초기화하지 않고 업데이트한다.
- 실제 기기에서 `flutter drive`는 기본 종료 동작으로 앱을 삭제하므로 반드시 `--keep-app-running`을 사용한다. 기존 데이터가 있는 앱을 대상으로 테스트할 때는 설치 전에 앱 데이터 폴더 전체를 백업하고, 메모리 저장소로 테스트한다. 테스트 후 일반 릴리스 빌드로 업데이트하며 저장 데이터도 다시 확인한다.
- 아이패드가 연결되지 않았거나 잠금·서명·권한 문제로 설치가 불가능하면 코드 수정과 기기 반영 상태를 구분해서 사용자에게 알린다. 설치에 성공했다고 추정하지 않는다.
- 코드 검토·설명만 하는 작업이나 문서만 수정하는 작업에는 재설치가 필요하지 않다. 사용자가 빌드·설치를 하지 말라고 하면 그 지시를 우선한다.
