# 이미지 주소 만료 검증 — 2026-10-31

## 결론

현재 구조에서 **서명 URL 만료 때문에 정상 저장된 친구 이미지가 사라지는 문제는 발견하지 못했다.**
앱은 이미지를 처음 받을 때 기기에 PNG 파일로 저장하고, 이후에는 만료된 주소가 아닌 로컬
파일을 읽는다. 저장된 이미지가 없는 새 로컬 저장소에서는 친구 목록을 다시 요청해 새 주소로
내려받는다. 운영 코드와 운영 설정은 변경하지 않았다.

## 실제 확인 결과

실제 Flutter/Dart 클라이언트 → 로컬 HTTP FastAPI → 개발 Supabase Auth·DB·Storage를 사용했다.
전용 임시 계정 하나와 합성 PNG·성공 상태의 진단 작업만 만들었고, 유료 AI 호출은 0회다.
진단 작업은 처음부터 `succeeded`로 넣어 실제 생성 대기열에 올라가지 않게 했다.

| 확인 | 결과 |
|---|---|
| 친구 이미지·썸네일 최초 다운로드와 PNG 디코딩 | 성공 |
| 실제로 만료된 옛 Storage 주소 재사용 | HTTP 400으로 거절 |
| 만료 후 오프라인에서 저장소 객체를 새로 만들어 친구 복원 | 이미지·썸네일 정상 디코딩, HTTP 요청 0회 |
| 친구의 영속 저장 데이터 | 로컬 파일 경로 사용, 서명 URL 저장하지 않음 |
| 같은 친구를 서버에서 다시 조회 | 같은 assetId에 새 URL·만료 시각 반환, 다운로드 성공 |
| 빈 로컬 저장소에서 친구 목록 복원 | 새 URL로 이미지·썸네일 다운로드·저장 성공 |
| 저장된 생성 작업 ID로 완료 결과 다시 가져오기 | 새 URL로 다운로드·저장 성공 |

Flutter의 실서비스 진단 테스트 1개에 위 항목들을 포함했고 종료 코드는 0이었다.
Python 진단 스크립트의 Ruff 검사·포맷 검사도 통과했다.

## 구현 근거

- `frontend/lib/src/data/api/device_art.dart`: PNG를 검사하고 기기의 파일로 저장한다.
- `frontend/lib/src/data/api/synced_character_repository.dart`: `pull()`에서 새 친구의 파일을
  다운로드·저장한다. 이미 로컬에 있는 친구는 재다운로드하지 않는다.
- `frontend/lib/src/data/api/api_services.dart`: 완료된 생성 작업을 다시 조회해 최신 이미지
  주소를 받고, 다운로드한 결과를 로컬 파일로 저장한다.
- `server/app/routers/characters.py`, `server/app/assets.py`: 목록·상세 조회 때 서명 URL을 발급한다.

즉, 기존 친구를 보여 줄 때마다 주소를 갱신하는 구조가 아니다. 이미지를 기기에 가지고 있으면
그 파일로 표시하고, 서버에서 이미지를 새로 가져올 때 최신 주소를 받는 구조다.

## 범위와 한계

운영 기본 TTL은 3,600초다. 한 시간을 기다리는 대신 **이번 진단 프로세스의 Storage 의존성만
TTL 4초로 주입**하고, 9초 경과 후 실제 거절과 복구를 확인했다. 서버·Storage의 시계를 조작하거나
운영 설정·버킷 정책·원격 스키마를 변경하지 않았다.

오프라인 재실행은 같은 디스크 파일을 쓰는 새 저장소 객체를 만들어 검증했다. 아이패드의 앱
프로세스를 직접 종료·실행하거나 실제 화면을 조작한 검증은 아니다. Windows 경로 표시 문제를
우회해 앱을 수정하지 않았으며, 저장한 파일을 직접 읽고 Flutter 이미지 디코더로 확인했다.

최초 다운로드 도중 연결이 끊기는 모든 경우나 파일 손상을 검증했다는 뜻은 아니다. 이번 판정은
사용자가 요청한 이미지 URL 만료와 정상 저장 파일·재다운로드 흐름에 한정한다.

## 증거·재실행·정리

- 결과: `output/diagnosis/signed-url-lifecycle.json`
- Dart 검증: `frontend/test/signed_url_lifecycle_live_test.dart`
- 실행기: `server/scripts/verify_signed_url_lifecycle.py`

`server/`에서 실행한다. 프로그램이 기존 서버 설정을 내부적으로 사용하며 비밀값이나 서명 URL을
출력하지 않는다. 기존 결과 파일이 있으면 덮어쓰지 않고 중단한다.

```powershell
.\.venv\Scripts\python.exe -B -m scripts.verify_signed_url_lifecycle
```

Flutter 의존성과 빌드 산출물은 시스템 TEMP에 복사한 소스에만 생성했다. 원래 앱의 소스·설정·
잠금 파일은 유지했다. 진단 계정과 그 계정 소유의 Storage 파일을 삭제하고, DB에서 해당 계정이
없음을 확인했다. 전역 생성 워커·복구·자동 정리는 시작하지 않았다. 진단 서버와 직접 만든 TEMP
프로젝트·기기 저장소를 정리했고 최종 증거는 보존했다.
