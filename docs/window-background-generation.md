# 캐릭터 아트 기반 창문 배경 생성

2026-10-31 사용자 요청으로 추가했다. 팀 `main`의 `dae4dd5`를 기준으로,
`quasiaward/bogle_backend_try`의 `6fdc4bc`에서 배경 기능만 가져와 현재 구조에 맞췄다.
기존 FR-04 생성·FR-05 저장·FR-06 삭제·FR-11 이미지 표시와 연결한다.

## 입력과 생성 방식

1. 캐릭터 생성 결과 PNG와 썸네일을 비공개 Storage에 저장하고 다시 읽어 검증한다.
2. 캐릭터 생성 성공 직후 배경 작업을 DB 큐에 넣는다. 얼굴 분석·친구 설정·배경 완성을 기다려
   캐릭터 생성 성공을 늦추지 않는다. 배경 등록 실패도 캐릭터 생성 성공을 취소하지 않는다.
3. 별도 배경 워커가 소유자에게 속한 캐릭터 아트를 Storage에서 읽어 참조 이미지로 변환한다.
   원본 사진·이름·성격·좋아하는 것·JSON 메타데이터나 별도 이미지 분석 호출은 사용하지 않는다.
4. `window_images.day_prompt()`와 참조 이미지를 OpenRouter 이미지 API에 보낸다.
   모델은 캐릭터 생성과 같은 `openai/gpt-image-2.5-flare`, OpenAI 제공자 고정이다.
   `n=1`, `quality=medium`, `aspect_ratio=21:9`, `background=opaque`, fallback 없음.
5. 실제 PNG·단일 프레임·불투명도·가로 비율·빈 이미지 여부를 검사하고 2048×576으로 정규화한다.
   Storage 업로드 후 바이트를 다시 읽어 검증한 낮 이미지 한 장만 성공으로 게시한다.
6. 프론트는 `day`만 있어도 캐시에 저장한다. `night=null`이면 기존 야간 색상 보정을 사용한다.
   이전 낮·밤 쌍 형식도 계속 읽는다.

프롬프트 버전은 `bogle-window-art-only-v1-20261031`이다. 기존 프롬프트의 평면 그림책 스타일,
캐릭터 팔레트·외형 참고, 창문 안전 영역과 캐릭터·창틀·글자 제외 지시는 유지했다.
친구 설정과 메타데이터를 참고하라는 지시는 제거했다. 실제 풍경의 의미·화풍 품질은 실호출 후
시각 검토가 필요하며 파일 검사를 통과했다고 보장하지 않는다.

## API와 보관

- `GET /v1/characters/{id}/window-view`: 상태, `jobId`, `readyJobId`, `day`, `night`,
  `error`, `pollAfterMs`를 반환한다. 새 작업의 `night`는 null이다.
- `POST` 같은 경로: `Idempotency-Key`, `{"regenerate":false}`. 새 작업은 202,
  재전송·완성 결과 재사용·활성 작업 합치기는 200이다. 명시적 재생성만 `regenerate=true`다.
- 토큰 소유자만 읽고 생성한다. 다른 사용자와 없는 친구는 404이며 모든 새 테이블에 RLS를 적용한다.
- 생성 직후 예약한 작업은 `generationJobId`에 연결하고, 친구 저장 트랜잭션에서 친구 ID를 채운다.
  저장과 예약이 경합해도 같은 생성 작업의 배경은 한 번만 연결한다.
- 재생성 실패·처리 중에는 마지막 성공 배경을 유지한다. 삭제·임대 만료·시간 초과 후의 늦은
  결과는 게시하지 않는다. 친구 삭제 시 관련 배경 작업·파일도 함께 정리한다.
- 저장하지 않은 배경과 과거 종료 작업은 기존 미사용 에셋 보관 시간(기본 24시간)에 맞춰 정리한다.
  저장한 친구의 최신 작업·마지막 성공 배경은 유지한다.

## 이번 통합의 실행 설정

- `WINDOW_PREFETCH_AFTER_GENERATION=true`: 캐릭터 생성 성공 후 미리 생성. 끄면 집 진입 때 요청한다.
- `WINDOW_GENERATION_TIMEOUT_SECONDS=240`: 배경 작업 전체 시간 한도. 설정 범위는 0초 초과~480초다.
- 배경 동시 처리 1개. 캐릭터 생성 큐와 독립적이므로 다른 캐릭터 생성·얼굴 분석과 병렬 실행한다.
- 배경 전용 사용자 한도는 시간당 10개다. 친구 생성 한도를 차감하지 않고, 재전송은 차감하지 않는다.
- 실패한 유료 AI 호출은 자동 재시도하지 않는다. 사용자가 재생성을 요청할 수 있다.
- 저장하지 않고 버린 캐릭터도 이미 배경을 생성했다면 이미지 한 장의 비용이 발생할 수 있다.

## 적용과 검증

추가 마이그레이션은 `20261031143705_window_background_generation.sql`이다.
기존 마이그레이션은 변경하지 않는다. DB 마이그레이션 → 서버 배포 순서로 적용하며,
앱에는 이 브랜치의 낮 단일 결과 지원을 함께 반영해야 한다.
원격 DB·서버 배포와 실제 AI 호출은 이 코드 통합에 포함하지 않는다.

자동 검증은 실제 임시 PostgreSQL과 모의 AI·Storage를 사용한다. 생성된 아트와 원본의 구분,
서로 다른 생성 결과의 연결, 메타데이터 제외, 중복 방지, 소유권·RLS, 저장 전후 연결,
실패 시 캐릭터·이전 배경 유지, 읽기 검증과 삭제·미사용 정리를 확인한다.
Flutter에서는 낮 한 장 다운로드·오프라인 재사용·삭제, 기존 낮·밤 쌍 표시를 확인한다.
