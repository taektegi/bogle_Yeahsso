요청서는 돌봄·찜·수정·복구·주문까지 포함한 넓은 범위를 전제합니다. 백엔드는 **2주 시연용 데모**로 범위를 줄이기로 결정했습니다 (2026-10-05). 아래 기능은 서버에 만들지 않으므로 앱의 해당 UI·로컬 동작을 정리해 주세요.

| 요청서의 기능 | 결정 | 근거 |
|---|---|---|

| 찜 (`/me/favorites`, `isFavorite`) | ❌ 보관함·마이페이지의 하트 제거 | D-24 |

### 확인이 필요한 것: Flutter 연동은 누가 작성하나요?
요청서는 "프론트엔드 어댑터를 붙인다"고 쓰고 있습니다. 백엔드 쪽 결정은 **백엔드 담당 3인이 Flutter 연동 코드까지 작성**하는 것입니다 (D-04). 일정과 분업이 이 결정을 기준으로 짜여 있어서, 연동 코드를 누가 쓰는지 먼저 맞춰야 합니다.

## 1. 공통 규약 ✅

| 항목 | 규칙 |
|---|---|
| 경로 | `/v1` 접두어. API 문서(OpenAPI)는 서버의 `/docs` |
| 인증 | `Authorization: Bearer <Supabase 액세스 토큰>`. 로그인은 앱이 Supabase Auth(Google)로 직접 처리. 서버는 토큰에서만 사용자를 식별 |
| JSON | 필드는 camelCase, 시각은 UTC ISO 8601 |
| 소유권 | 다른 사용자의 `assetId`, `jobId`, `characterId`는 **404**(없는 것과 같은 응답) |
| 중복 방지 | 생성 계열 요청은 `Idempotency-Key` 헤더, 대화는 `clientMessageId` |
| 추적 | 응답 헤더 `X-Request-Id` (앱이 같은 헤더를 보내면 그 값을 사용). 오류 본문의 `requestId`와 같음 |
| 파일 접근 | 모든 이미지는 비공개 저장소의 **만료되는 서명 URL**로만 제공 |

### 오류 형식
모든 오류는 같은 모양입니다.

```json
{
  "error": {
    "code": "validation_error",
    "message": "입력값을 확인해 주세요.",
    "retryable": false,
    "fieldErrors": {"name": "string_too_short"},
    "requestId": "6f1c0c9a2d7b4e0f8a3b5c7d9e1f2a4b"
  }
}
```

- `code`는 앱이 분기에 쓰는 안정적인 영어 코드, `message`는 사용자에게 보여 줄 수 있는 한국어 문구입니다.
- `retryable`은 같은 요청을 다시 보내면 성공할 수 있는 일시 오류일 때만 `true`입니다.
- `fieldErrors`는 입력 검증 실패(422) 때만 채워지며 `{필드: 오류 종류}`입니다. 🟡 값을 영어 종류 코드(`string_too_short`, `missing` 등)로 했는데, 앱에서 쓰기 불편하면 알려 주세요.
- 자주 쓰는 상태 코드: 401 `unauthenticated`, 404 `not_found`, 409 상태 충돌, 422 `validation_error`, 429 `rate_limited`.

## 2. 이미지 에셋과 생성 작업

### 2.1 이미지 참조 방식 🟡
요청서의 "안정적인 assetId와 URL 갱신 방법" 요청에 대한 제안입니다.

- 모든 이미지는 안정적인 `assetId`를 가지고, 응답에서는 아래 객체로 내려 줍니다.

```json
{
  "assetId": "3f2a9c1e-5b7d-4c8a-9e0f-1a2b3c4d5e6f",
  "url": "https://<storage>/...signed...",
  "expiresAt": "2026-10-05T05:30:00Z",
  "contentType": "image/png"
}
```

- `url`은 만료됩니다. 만료 후에는 `GET /v1/assets/{assetId}`로 새 `url`과 `expiresAt`을 받습니다. 목록·상세를 다시 조회해도 새 URL이 내려옵니다.
- 앱은 화면에 쓰는 동안만 `url`을 쓰고, 영구 저장 키로는 `assetId`를 쓰세요.
- 서버에는 모든 이미지(원본, 캐릭터 아트, 썸네일, 모션 GIF)를 한 곳에서 관리하는 `assets` 테이블을 둡니다 (`supabase/migrations/20261005000200_assets.sql`). `assetId`는 이 테이블의 ID이고, 소유권·크기·해상도도 여기에 기록됩니다.

### 2.2 업로드 `POST /v1/assets` 🟡
- multipart로 `file`과 `kind`(`drawing`: 그림판 PNG, `photo`: 카메라·사진 JPEG)를 보냅니다.
- 서버가 **실제 파일 형식**(PNG/JPEG), 크기, 해상도를 검사합니다. 통과하면 `{"assetId": "...", "kind": "photo", "createdAt": "..."}`를 돌려줍니다.
- 크기·해상도 상한은 개발 중 실측해서 정합니다 (OI-06). 확정되면 이 문서에 적겠습니다. 그림판은 화면 확대와 무관한 원본 캔버스 PNG를 보내 주세요 (FR-03.2).

### 2.3 생성 작업 ✅ 경로·상태, 🟡 세부 값

| 동작 | 경로 |
|---|---|
| 시작 | `POST /v1/generations` |
| 조회 | `GET /v1/generations/{jobId}` |
| 취소 | `POST /v1/generations/{jobId}/cancel` |

**시작** (헤더 `Idempotency-Key` 필수)

```json
{"sourceAssetId": "3f2a9c1e-...", "sourceType": "photo"}
```

접수 응답 `202`:

```json
{"jobId": "9b1d...", "status": "queued", "createdAt": "2026-10-05T05:00:00Z", "pollAfterMs": 2000}
```

- 같은 `Idempotency-Key`로 다시 보내면 **같은 작업**을 돌려줍니다. 중복 클릭, 백그라운드 복귀 후 재요청에서도 작업은 하나만 생깁니다.
- 서버가 이미지를 보내는 외부 AI(OpenAI)는 시연용 계정 한정으로 허용된 상태입니다 (D-11).

**상태** `queued → processing → succeeded | failed | cancelled` ✅
- 진행률은 서버가 알 수 없으므로 **퍼센트를 내려 주지 않습니다.** 앱의 30초·75초 안내 문구는 앱의 경과 시간으로 계속 처리해 주세요.
- 상태 응답에는 `pollAfterMs`(다음 조회까지 권장 대기)가 들어 있습니다.

**성공**

```json
{
  "jobId": "9b1d...", "status": "succeeded",
  "sourceAssetId": "3f2a9c1e-...",
  "art":       {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png"},
  "thumbnail": {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png"},
  "accentArgb": 4289974783
}
```

- `succeeded`는 결과 파일을 **실제로 읽을 수 있을 때만** 내려갑니다 (FR-04.3).
- 결과는 항상 **배경이 투명한 캐릭터 PNG 1장**입니다 (D-10). 그래서 `presentationType`(cutout/paperPhoto)은 두지 않습니다. 사진형 카드 스타일(`archive_*`)을 계속 쓸지는 기획 미결(OI-09)이고, 계속 쓴다면 명시 필드를 추가하겠습니다.
- `accentArgb`는 서버가 결과 PNG에서 뽑은 대표색입니다. 부호 없는 32비트(최대 4294967295)이므로 앱에서 정수 범위에 주의하세요.

**실패**

```json
{"jobId": "9b1d...", "status": "failed",
 "error": {"code": "generation_unavailable", "message": "...", "retryable": true}}
```

| 코드 | 의미 | `retryable` |
|---|---|---|
| `generation_rejected` | AI가 입력 이미지를 처리하지 못함·정책 위반 (모델 쪽 거부) | false |
| `invalid_source_image` | 입력 이미지 문제 | false |
| `generation_timeout` | 서버 작업 시간 초과 | true |
| `generation_unavailable` | 일시적 서버·외부 서비스 장애 | true |

- 모델이 못 만드는 경우(`generation_rejected`)와 서버 장애(`generation_unavailable`)는 코드로 구분됩니다.
- 🟡 **재시도 방법**: `retryable: true`면 같은 `sourceAssetId`로 **새 `Idempotency-Key`를 붙여 `POST /v1/generations`를 다시** 호출합니다. 같은 키로 재호출하면 같은(실패한) 작업이 그대로 돌아옵니다. "실패한 작업 재실행" 전용 API는 두지 않습니다 (FR-04.7).

**취소** `POST /v1/generations/{jobId}/cancel`
- 응답은 서버가 판단한 **최종 상태**입니다: `{"jobId": "...", "status": "cancelled" | "succeeded" | "failed"}`.
- 취소와 완료가 동시에 일어나면 `succeeded`가 올 수 있습니다. 이때 앱은 **사용자가 취소한 시도의 늦은 결과로 다음 화면에 넘어가지 않아야** 합니다 (FR-04.5). 앱이 화면을 떠난 것과 서버 작업 취소는 별개이며, 서버는 `cancel`을 받았을 때만 취소합니다.

**앱 대기 시간과 서버 최대 시간** 🟡
- 앱의 5분 UI 한도와 서버 작업 최대 시간은 별개입니다. 서버 목표는 **4분 이내**이며, 넘으면 `failed(generation_timeout)`로 끝냅니다. 실측 후 확정하고 앱의 30초·75초 안내는 그대로 유지합니다.
- 앱의 5분 시간 초과는 서버 실패가 아니므로, 같은 `jobId`로 다시 조회할 수 있습니다 (FR-04.6).
- API는 UI 애니메이션 상태와 무관합니다. 빠른 성공도 앱이 연출을 마친 뒤 다음 단계로 넘어가면 되고, 백그라운드에서는 이동하지 않아도 됩니다.

**복구**
- 앱이 종료됐다가 돌아오면 저장해 둔 `jobId`로 최종 상태를 조회합니다. 🟡 작업은 **생성 후 24시간** 동안 조회할 수 있고, 이후에는 404입니다.

## 3. 친구 (캐릭터) ✅ 범위, 🟡 필드·세부

요청서의 경로(`/v1/characters`)를 따릅니다. (서버 DB 테이블 이름은 `friends`지만 API 경로는 앱 모델 `CharacterFriend`에 맞춥니다.)

| 동작 | 경로 | 비고 |
|---|---|---|
| 생성 | `POST /v1/characters` | `Idempotency-Key` 필수 |
| 목록 | `GET /v1/characters` | 내 친구, 최신순 |
| 상세 | `GET /v1/characters/{id}` | |
| 삭제 | `DELETE /v1/characters/{id}` | 즉시 영구 삭제, `204` |
| ~~수정~~ | ❌ | D-24 |
| ~~복구~~ | ❌ | D-21 |

### 생성 요청

```json
{
  "generationJobId": "9b1d...",
  "name": "구름이",
  "personalityType": "calm",
  "favoriteThings": ["구름", "사과"],
  "speechStyle": "해요체"
}
```

| 필드 | 규칙 |
|---|---|
| `generationJobId` | 내 작업이고 `succeeded`여야 함. **작업 하나로는 친구 하나만** 만들 수 있음 |
| `name` | 공백 제거 후 1–12자. 글자 수는 사용자에게 보이는 글자(grapheme) 기준 |
| `personalityType` | **서버가 관리하는 성격 유형 목록 중 하나** (객관식, 자유 입력 아님). 목록은 `GET /v1/personality-types` → `[{"code","label"}]`. 목록 내용은 기획 미결(OI-01) |
| `favoriteThings` | 1개 이상. 현재 선택지 8개(사과, 친구랑 놀기, 산책, 구름, 낮잠, 그림, 노래, 바다) 안에서만 허용 (OI-02에서 목록 확정) |
| `speechStyle` | `~지요!`, `해요체`, `반말` 중 하나 |

- 이름·성격·좋아하는 것·말투가 모두 필요합니다. **편집 화면이 없어지므로**(D-24) 요청서가 물은 "성격 빈 값 허용", "성격 최대 30자", "소개문 편집"은 해당이 없습니다.
- 요청서가 말한 "자유 서술형 말투·데모 취향 값"은 **서버로 옮기지 않습니다.** 데모 친구(뭉글이·뚜치·네모린)는 서버 데이터가 아니라서 이관 규칙이 필요 없습니다 (A-08).
- 클라이언트가 보낸 이미지 경로·색상은 쓰지 않습니다. 이미지와 대표색은 서버가 `generationJobId`의 결과에서 가져옵니다 (FR-05.3).

### 응답 (Character)

```json
{
  "id": "5d0e...",
  "name": "구름이",
  "personalityType": "calm",
  "introduction": "하늘 위에서 놀다 왔어!",
  "favoriteThings": ["구름", "사과"],
  "speechStyle": "해요체",
  "source":    {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png"},
  "art":       {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png"},
  "thumbnail": {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png"},
  "accentArgb": 4289974783,
  "createdAt": "2026-10-05T05:01:00Z"
}
```

- 요청서 제안에서 **빠진 필드**: `level`, `memories`, `sleepSchedule`, `isFavorite`, `revision` (모두 범위 밖).
- `introduction`은 저장 직후 서버가 소개 문구(최대 70자)를 AI로 만들어 응답에 넣으려고 시도합니다. 🟡 대기 한도는 10초이며, **실패하면 친구 저장은 성공하고 `introduction`은 빈 문자열**입니다. 앱은 빈 문자열이면 기본 소개문을 보여 주세요 (FR-05.4).
- 🟡 `source`(원본)를 앱 화면에 보여 줘야 하는지 확인이 필요합니다. 요청서는 "집 벽의 그림"에 쓴다고 했는데, 백엔드 가정은 "원본은 보관만 하고 화면에는 쓰지 않는다"(A-04)였습니다. 쓰신다면 현재 응답처럼 `source`를 내려 드리고, 쓰지 않으면 응답에서 뺍니다.
- 이미지 URL은 만료되므로 2.1의 갱신 방법을 따르세요.

### 생성 응답 코드와 오류

| 상황 | 응답 |
|---|---|
| 성공 | `201` + Character |
| 같은 `Idempotency-Key` 재요청 | 같은 친구를 돌려줌 (두 번 만들어지지 않음) |
| 작업이 아직 `succeeded`가 아님 | 409 `generation_not_ready` |
| 다른 키로 이미 사용한 작업 | 409 `generation_job_already_used` |
| 남의 작업, 없는 작업 | 404 `not_found` |
| 입력 검증 실패 | 422 `validation_error` + `fieldErrors` |

### 목록
```json
{"items": [ {Character}, ... ], "nextCursor": null}
```
- 최신순입니다 (OI-07 기본값). 데모 규모라 한 번에 내려 주며, `limit`·`cursor`는 선택 사항입니다. 보유 친구 수는 `GET /v1/me`의 `characterCount`로 받으세요.

### 삭제
- 친구를 지우면 **그 친구의 대화 기록, 모션 결과, 원본·캐릭터 아트·썸네일 파일이 함께 삭제**됩니다 (FR-06.3). 되돌릴 수 없으므로 앱의 삭제 전 확인은 유지해 주세요.
- 지운 친구가 **프로필 아바타**였다면 아바타가 기본값(`null`)으로 바뀝니다.
- 과거 주문 스냅샷 보존은 주문 범위 밖(D-22)이라 해당이 없습니다.
- 삭제가 실패하면 성공으로 응답하지 않습니다.

## 4. 프로필 ✅ 범위, 🟡 필드

요청서 경로를 따릅니다: `GET /v1/me`, `PATCH /v1/me`. 찜 API는 ❌입니다.

```json
{
  "nickname": "그린고블린",
  "avatarCharacterId": null,
  "friendNotifications": true,
  "orderNotifications": true,
  "characterCount": 2
}
```

- 처음 로그인하면 서버가 프로필을 만듭니다. 기본 닉네임은 `그린고블린`입니다. 계정 하나가 아이 프로필 하나입니다 (요청 D-01의 답).
- `PATCH`는 보낸 필드만 수정합니다(부분 수정). 닉네임은 공백 제거 후 1–12자입니다. `avatarCharacterId`는 **내 친구만** 지정할 수 있고(아니면 422), `null`은 기본 아바타입니다.
- 집계는 `characterCount`(보유 친구 수)만 제공합니다. 추억 합계는 삭제됐고(D-14), "진행 중 주문 수"는 앱 mock을 그대로 쓰세요(D-22). 친구를 만들거나 지우면 다음 조회에 바로 반영됩니다.
- 알림 플래그는 **저장만** 하고 푸시는 보내지 않습니다.

## 5. 친구의 집

### 5.1 수면 상태 ✅
`GET /v1/characters/{id}/status`

```json
{"asleep": false, "nextChangeAt": "2026-10-05T13:00:00Z", "serverTime": "2026-10-05T05:00:00Z"}
```

- 모든 친구가 한국 시간(Asia/Seoul) 22:00–06:00에 잡니다. 판정은 **서버 시각 기준**이고 `nextChangeAt`은 다음 전환 시각입니다.
- 앱은 같은 규칙으로 화면을 미리 바꿀 수 있지만 기준은 서버입니다. 기기 시계가 어긋났을 때 보정할 수 있도록 `serverTime`을 함께 줍니다.
- 자는 동안에는 서버도 대화를 거부합니다 (아래 5.2). 간식은 앱 안의 모션뿐이므로 서버를 호출하지 않으며, 자는 동안 막는 것은 앱이 합니다.
- 요청서가 물은 **수동 재우기/깨우기와 자동 일정의 충돌, 시간대·여행, 기상 보상 중복 문제는 해당이 없습니다.** 수동 조작, 일정 편집, 상태 수치가 모두 없기 때문입니다.

### 5.2 대화 ✅ 범위, 🟡 세부
요청서는 생성형 대화를 후속 범위로 분리할 수 있다고 했지만, 백엔드는 **이번 범위에 포함**합니다 (D-16).

`POST /v1/characters/{id}/messages`

```json
{"clientMessageId": "client-msg-0001", "text": "오늘 뭐 했어?"}
```

응답 `200`:

```json
{
  "userMessage":      {"id": "...", "role": "user",      "text": "오늘 뭐 했어?", "createdAt": "..."},
  "assistantMessage": {"id": "...", "role": "assistant", "text": "구름 구경했지요!", "source": "ai", "createdAt": "..."}
}
```

- `source`는 답의 출처입니다: `ai`(생성형) 또는 `script`(기존 스크립트 대사로 대체).
- 같은 `clientMessageId`로 다시 보내면 **새로 기록하거나 답을 다시 만들지 않고 이전 결과를 그대로** 돌려줍니다.
- 입력과 AI 답변을 모두 검열하며, 문제가 있거나 AI 호출이 실패·시간 초과(🟡 15초)되면 오류가 아니라 **스크립트 대사(`source: "script"`)로 정상 응답**합니다. 오류로 막히는 경우는 아래와 같습니다.

| 상황 | 응답 |
|---|---|
| 자는 시간 | 409 `character_asleep` |
| 빈 메시지, 길이 초과 | 422 `validation_error` (길이 상한은 개발 중 정함, 제안 200자 — OI-04) |
| 요청 횟수 초과 | 429 `rate_limited` (한도는 OI-05) |

- 빠른 답 버튼 4종도 같은 API로 보냅니다.
- 요청서의 `characterProgress`(추억·레벨)와 `status`(기분·친밀도) 응답은 **없습니다.** 대화는 상태·성장·캐릭터 설정에 영향을 주지 않습니다 (D-14, D-17).

`GET /v1/characters/{id}/messages?limit=30&before=<cursor>`
- 요청서가 물은 이력 복원은 **지원합니다.** 친구의 집에 다시 들어오면 이전 대화를 최신순으로 불러옵니다 (FR-09.7). 응답은 `{"items": [...], "nextCursor": "..."}`입니다.
- 🟡 보관: 친구가 삭제될 때까지 서버에 저장합니다 (요청 D-08). AI 문맥에는 최근 N개를 사용합니다(N은 OI-04).

## 6. 모션 ✅ 통합, 🟡 응답 세부

모션 서버는 별도 서버로 유지하지 않고 **백엔드에 통합**합니다. 인증, 작업 큐, 파일 저장소를 친구 생성과 같은 방식으로 씁니다 (D-12, 요청 D-12의 답).

- **입력**: 친구의 **생성된 투명 PNG**입니다 (원본이 아님). 생성 아트가 모션 조건에 맞는지는 초기에 실측해서 확인합니다 (OI-08).
- **시작**: 친구가 저장되면 서버가 **자동으로** 모션 작업을 시작합니다. 앱이 따로 요청하지 않습니다.
- **조회**: 🟡 `GET /v1/characters/{id}/motion`

```json
{
  "status": "ready",
  "reason": null,
  "clips": {
    "jump":  {"url": "https://...signed.gif", "box": [0.12, 0.05, 0.88, 0.97]},
    "wave":  {"url": "...", "box": [0.12, 0.05, 0.88, 0.97]},
    "dance": {"url": "...", "box": [0.12, 0.05, 0.88, 0.97]}
  }
}
```

- `status`는 기존과 같은 값(`queued`, `working`, `ready`, `unsupported`, `failed`)과 `reason`(`not_humanoid`, `background`, `no_figure`)을 씁니다. `clips[clip]`의 `url`·`box`(0–1 비율 `[left, top, right, bottom]`) 구조도 기존과 같아서 현재 클라이언트의 해석 코드를 크게 바꾸지 않아도 됩니다.
- **호환 주의**: 현재 클라이언트는 HTTP 200만 성공으로 처리합니다. 이 API는 작업이 처리 중이어도 상태를 `200`으로 내려 주고, 친구가 없거나 남의 친구면 404입니다.
- GIF는 소유자만 만료되는 서명 URL로 받을 수 있습니다. 내용 해시만으로 다른 사용자와 결과를 공유하지 않습니다 (FR-10.4).
- **모션은 선택 기능**입니다. `unsupported`, `failed`, 처리 중이면 앱 기본 애니메이션을 쓰세요. 모션 실패가 친구 생성 실패는 아닙니다 (FR-10.5). 서버가 재시작돼도 미완료 작업은 다시 처리합니다.
- 기존 클라이언트는 2초 간격 조회, 약 3분 뒤 포기 방식입니다. 같은 방식으로 계속 쓰셔도 됩니다.

## 7. 파일·데이터 보관과 삭제 규칙 🟡

요청서가 요구한 임시 파일 보관 기간, 취소 시 삭제, 이용자 삭제 규칙입니다. **기간은 제안이며 팀 확인 후 확정**합니다 (OI-06).

| 대상·상황 | 규칙 |
|---|---|
| 업로드 원본, 생성이 **실패**한 경우 | 재시도를 위해 **24시간 보관**. 같은 `sourceAssetId`로 새 작업을 만들 수 있음 |
| 친구로 저장되지 않은 업로드·생성 결과·작업 기록 | **24시간 뒤 삭제** (FR-04.8) |
| 생성 중 **취소** | 해당 작업의 결과 파일은 즉시 삭제. 원본은 재시도할 수 있게 24시간 유지 후 삭제 |
| 친구로 **저장된 후** | 원본·캐릭터 아트·썸네일을 친구와 함께 보관 |
| 친구 **삭제** | 친구, 대화 기록, 모션 작업·결과, 원본·아트·썸네일을 즉시 영구 삭제 |
| 작업(`jobId`) 조회 가능 기간 | 생성 후 24시간 |
| 이용자 **삭제/탈퇴** | 앱의 탈퇴 기능은 없음(A-07). 시연이 끝나면 **운영자가** 계정을 삭제하고, 계정 삭제 시 프로필·친구·대화 등 DB 데이터는 함께 지워짐. 저장소 파일은 DB가 지우지 못해서 **정리 스크립트로 별도 삭제** |
| 접근 범위 | 파일·작업·친구·대화 모두 **소유자 본인만** (타인의 ID는 404) |

- 대화 원문, 그림·사진은 일반 서버 로그에 남기지 않습니다. 시연용 계정만 사용하며 실제 아동 데이터는 받지 않습니다 (D-09).

## 9. 인수 기준(요청서 8절)에 대한 범위

| 요청서의 연속 흐름 | 이번 범위 |
|---|---|
| 1. 사진·그림 → 생성 → 상태 조회 → 결과 조회 → 친구 저장 → 재실행 후 목록·집 조회 | ✅ 포함 |
| 2. 소개문 수정, 찜, 수면 시간 수정 → 행동·대화 보상 → 삭제·복구 정합성 | ❌ 수정·찜·수면 편집·보상·복구 없음. **삭제 시 아바타 기본값 복귀, 연쇄 삭제**와 **대화 중복 전송 방지**는 포함 |
| 3. 견적 → 배송지·동의 → 주문·결제 → 제작/배송 상태 | ❌ 범위 밖 |
| 4. 다른 사용자의 `assetId`, `jobId`, `characterId`로 조회·수정 시 차단 | ✅ 포함 (`addressId`, `orderId`는 범위 밖) |
| 5. 네트워크 실패·중복 클릭·동일 키 재시도·상태 충돌·모션 미지원 | ✅ 포함 (만료 견적은 범위 밖) |

**스테이징 환경**: 요청서는 스테이징에서 위 흐름을 재현하길 요청합니다. 현재 백엔드에는 **배포 환경이 아직 없습니다.** 시연용과 개발용 환경은 분리할 예정(NFR-11)이며, 배포 시점이 정해지면 알려 드리겠습니다. 그 전까지는 서버를 로컬에서 띄운 `/docs` 문서와 시드 데이터(테스트용 친구)로 확인하실 수 있게 준비합니다.
