| 항목 | 내용 |
|---|---|
| 작성일 | 2026-10-05 |
| 상태 | **백엔드 확정안 (v1)** — 프론트엔드 확인 요청 |
| 대상 | 프론트엔드 개발자 (요청서: 생성 작업·친구·프로필·집·모션·주문 API 요청) |
| 근거 문서 | `aidlc-docs/inception/requirements/requirements.md` (이하 `D-xx`, `FR-xx`, `OI-xx`는 이 문서의 번호) |

> 요청서의 결정 번호(D-01~D-12)와 requirements.md의 `D-xx`는 **다른 번호 체계**입니다. 요청서의 번호는 "요청 D-01"처럼 씁니다.

## 0. 먼저 읽어 주세요

### 이 문서의 위치
- 요청서에서 백엔드가 정해야 한다고 물은 항목을 **모두 정했습니다.** 숫자와 이름까지 확정값이므로 앱은 이 값을 기준으로 개발해 주세요.
- 서버를 띄우면 열리는 **`/docs`(OpenAPI)** 가 최종 계약입니다. 엔드포인트가 구현되면 `/docs`를 기준으로 하고, 이 문서와 다르면 `/docs`가 맞습니다. 계약이 바뀌면 바로 알려 드립니다.
- 확인이 필요한 것은 12절에 모았습니다.

### 표기
- ✅ **확정**: 백엔드가 확정한 내용입니다.
- ❌ **범위 밖**: 이번 범위에서 만들지 않습니다.
- ❓ **프론트 확인 필요**: 프론트엔드의 답이 있어야 닫히는 항목입니다.

### 한눈에 보기
1. 요청서의 **수정·찜·복구·돌봄 수치·초대·수면 일정 편집·주문/결제는 이번 범위 밖**입니다 (1절). 앱의 해당 UI·로컬 동작을 정리해 주세요.
2. **생성 작업·친구·프로필·수면 상태·대화 API는 만듭니다.** 모션은 Flutter가 담당하고 서버는 생성·친구 응답에 얼굴 좌표를 제공합니다.
3. 모든 이미지는 **`assetId` + 만료되는 서명 URL**로 내려갑니다.
4. 기본 수면 시간은 요청서의 21:00–07:00이 아니라 **22:00–06:00(한국 시간) 고정**입니다.

## 2. 공통 규약 ✅

| 항목 | 규칙 |
|---|---|
| 경로 | `/v1` 접두어. API 문서는 서버의 `/docs` |
| 인증 | `Authorization: Bearer <Supabase 액세스 토큰>`. 로그인은 앱이 Supabase Auth(Google)로 직접 처리. 서버는 토큰에서만 사용자를 식별. 토큰이 만료되어 401이 오면 앱이 Supabase SDK로 토큰을 갱신한 뒤 **한 번만** 다시 요청 |
| JSON | 필드는 camelCase. 시각은 UTC ISO 8601 (`2026-10-05T05:00:00Z`) |
| 소유권 | 다른 사용자의 `assetId`, `jobId`, `characterId`는 **404 `not_found`**(없는 것과 같은 응답) |
| 추적 | 응답 헤더 `X-Request-Id`. 앱이 같은 헤더(8–64자 영문·숫자·`-`·`_`)를 보내면 그 값을 쓰고, 오류 본문의 `requestId`와 같음 |
| 파일 접근 | 모든 이미지는 비공개 저장소의 **서명 URL**로만 제공. URL 유효 시간은 **60분** |
| 중복 방지 | 생성 계열 요청은 `Idempotency-Key` 헤더, 대화는 `clientMessageId` |

### Idempotency-Key
- 형식: 8–64자 영문·숫자·`-`·`_` (UUID v4 권장). 요청 하나당 새로 만들고, **재전송할 때는 같은 값**을 씁니다.
- 대상: `POST /v1/generations`, `POST /v1/characters`
- 키는 그 요청으로 **만들어진 작업·친구가 서버에 있는 동안** 유지됩니다(최소 24시간). 작업은 24시간 뒤 정리되고 친구는 삭제할 때까지 남습니다. 키는 사용자별로 구분됩니다.
- 같은 키로 **다른 내용**을 보내면 409 `idempotency_key_conflict`입니다.
- `clientMessageId`도 같은 형식·규칙입니다 (대화 6.2절).

### 요청 횟수 제한 (429)
데모 비용 보호용입니다. 앱은 429를 받으면 `Retry-After` 헤더(초)만큼 기다려 달라는 안내를 보여 주세요. 시연 전에 값이 조정될 수 있습니다.

| 대상 | 한도 (사용자당) |
|---|---|
| `POST /v1/assets` | 1시간에 30회 |
| `POST /v1/generations` | 1시간에 10회 |
| `POST /v1/characters/{id}/messages` | 1분에 20회 |

### 오류 형식
모든 오류는 같은 모양입니다.

```json
{
  "error": {
    "code": "validation_error",
    "message": "입력값을 확인해 주세요.",
    "retryable": false,
    "fieldErrors": {"name": "string_too_short"},
    "requestId": "6f1c0c9a2d7b4e0f8a3b5c7d9e1f2a4b"
  }
}
```

- `code`는 앱이 분기에 쓰는 안정적인 영어 코드, `message`는 사용자에게 보여 줄 수 있는 한국어 문구입니다.
- `retryable`은 같은 요청을 다시 보내면 성공할 수 있는 일시 오류일 때만 `true`입니다.
- `fieldErrors`는 422일 때만 채워지며 `{필드 경로: 오류 종류}`입니다. 오류 종류는 영어 코드(`missing`, `string_too_short` 등)이고, 화면 문구는 앱이 정합니다. 오류가 없으면 빈 객체입니다.
- 오류 본문에 서버 내부 원인이나 스택 추적은 들어가지 않습니다.

### 오류 코드 목록

| 상태 | `code` | 상황 | `retryable` |
|---|---|---|---|
| 401 | `unauthenticated` | 토큰 없음·만료·위조 | false |
| 404 | `not_found` | 없거나 내 것이 아닌 리소스, 만료된 작업 | false |
| 405 | `method_not_allowed` | 허용되지 않는 메서드 | false |
| 409 | `idempotency_key_conflict` | 같은 키로 다른 내용 전송 | false |
| 409 | `generation_not_ready` | 친구 생성에 쓴 작업이 아직 `succeeded`가 아님 | false |
| 409 | `generation_job_already_used` | 이미 친구가 된 작업을 다른 키로 다시 사용 | false |
| 409 | `character_asleep` | 자는 시간에 대화 전송 | false |
| 413 | `file_too_large` | 업로드 파일 크기 초과 | false |
| 422 | `validation_error` | 입력값 검증 실패 (`fieldErrors` 있음) | false |
| 422 | `invalid_image` | 이미지 형식·크기(픽셀) 검사 실패 | false |
| 429 | `rate_limited` | 요청 횟수 초과 (`Retry-After` 헤더) | true |
| 500 | `internal_error` | 서버 내부 오류 | false |
| 503 | `service_unavailable` | 일시적 장애 | true |

생성 작업이 **실패 상태로 끝났을 때**의 오류 코드(`generation_*`)는 HTTP 오류가 아니라 작업 응답 본문에 들어갑니다 (3.3절).

## 3. 이미지 에셋과 생성 작업 ✅

### 3.1 이미지 참조 방식
모든 이미지(업로드 원본, 캐릭터 아트, 썸네일)는 안정적인 `assetId`를 가지고, 응답에서는 아래 객체로 내려갑니다.

```json
{
  "assetId": "3f2a9c1e-5b7d-4c8a-9e0f-1a2b3c4d5e6f",
  "url": "https://<storage>/...signed...",
  "expiresAt": "2026-10-05T06:00:00Z",
  "contentType": "image/png",
  "width": 1024,
  "height": 1024
}
```

- `url`은 **60분** 뒤 만료됩니다. 만료됐거나 곧 만료되면 `GET /v1/assets/{assetId}`로 같은 모양의 객체(새 `url`, `expiresAt`)를 받습니다. 친구 목록·상세를 다시 조회해도 새 URL이 내려옵니다.
- 앱은 화면에 쓰는 동안만 `url`을 쓰고, 영구 저장 키로는 `assetId`를 쓰세요. `width`·`height`는 렌더링과 경계 측정(FR-11.5)에 쓸 수 있습니다.
- `assetId`는 사용자 단위 소유권이 있어서 남의 `assetId`로 조회하면 404입니다.

### 3.2 업로드 `POST /v1/assets`
- 요청: `multipart/form-data`, 필드 `file` 하나. 응답 `201`은 위 이미지 참조 객체입니다.
- 그림판은 화면 확대와 무관한 **원본 캔버스 PNG**를, 사진은 카메라·사진 편집 화면이 만든 **JPEG**를 보내 주세요 (FR-03.2).

| 항목 | 한도 |
|---|---|
| 형식 | PNG 또는 JPEG. 서버가 파일 내용으로 실제 형식을 검사합니다 (확장자·`Content-Type` 헤더는 믿지 않음). **HEIC 등은 지원하지 않으므로 앱에서 JPEG로 변환**해 주세요 |
| 파일 크기 | 최대 **10 MiB** (10,485,760 bytes). 초과하면 413 `file_too_large` |
| 해상도 | 가로·세로 각각 **64px 이상 4096px 이하**. 벗어나면 422 `invalid_image` |

- 형식이 아니거나 이미지가 깨졌으면 422 `invalid_image`입니다.
- 업로드만 하고 생성을 시작하지 않으면 **24시간 뒤 자동 삭제**됩니다 (8절).
- 이 API는 `Idempotency-Key`가 필요 없습니다. 중복 업로드는 별도 에셋이 되고, 쓰이지 않은 것은 정리됩니다.

### 3.3 생성 작업

| 동작 | 경로 |
|---|---|
| 시작 | `POST /v1/generations` |
| 조회 | `GET /v1/generations/{jobId}` |
| 취소 | `POST /v1/generations/{jobId}/cancel` |

**시작** (헤더 `Idempotency-Key` 필수)

```json
{"sourceAssetId": "3f2a9c1e-...", "sourceType": "photo"}
```

- `sourceType`은 `drawing`(그림판) 또는 `photo`(촬영·보관함 사진)입니다. `sourceAssetId`는 내가 올린 원본이어야 하며 아니면 404입니다.
- 첫 요청은 `202`:

```json
{"jobId": "9b1d...", "status": "queued", "createdAt": "2026-10-05T05:00:00Z", "pollAfterMs": 2000}
```

- 같은 `Idempotency-Key`로 다시 보내면 **같은 작업**을 `200`으로, 그 시점의 상태와 함께 돌려줍니다. 중복 클릭, 백그라운드 복귀 후 재요청에서도 작업은 하나만 생깁니다.
- 서버가 이미지를 보내는 OpenRouter 및 선택 모델의 처리 제공자는 시연용 계정 한정으로 허용된 상태입니다 (D-11, D-25).

**조회** `GET /v1/generations/{jobId}`

공통 필드: `jobId`, `status`, `sourceAssetId`, `createdAt`, `updatedAt`.

| `status` | 의미 | 추가 필드 |
|---|---|---|
| `queued` | 접수됨 | `pollAfterMs` |
| `processing` | 생성 중 | `pollAfterMs` |
| `succeeded` | 성공 | `art`, `thumbnail`, `accentArgb`, `face` |
| `failed` | 실패 | `error` |
| `cancelled` | 취소됨 | — |

- 진행률은 서버가 알 수 없으므로 **퍼센트를 내려 주지 않습니다.** 앱의 30초·75초 안내 문구는 앱의 경과 시간으로 계속 처리해 주세요.
- `pollAfterMs`는 항상 **2000**입니다. 이 간격으로 조회해 주세요.

성공 응답:

```json
{
  "jobId": "9b1d...", "status": "succeeded",
  "sourceAssetId": "3f2a9c1e-...",
  "art":       {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png", "width": 1024, "height": 1024},
  "thumbnail": {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png", "width": 256, "height": 256},
  "accentArgb": 4289974783,
  "face": {"version": 1, "size": [1024, 1024], "facing": "front", "head": [250, 100, 520, 500], "eyes": [[410, 300, 42], [610, 300, 42]], "mouth": [510, 470, 130, 52], "cheeks": [[350, 420, 50], [670, 420, 50]]},
  "createdAt": "...", "updatedAt": "..."
}
```

- `succeeded`는 결과 파일을 **실제로 읽을 수 있을 때만** 내려갑니다 (FR-04.3).
- 결과는 항상 **배경이 투명한 캐릭터 PNG 1장**입니다 (D-10). 그래서 `presentationType`(cutout/paperPhoto) 필드는 **두지 않습니다.** 사진형 카드 스타일(`archive_*`)을 앱에서 계속 쓸지는 앱이 정하면 되고, 서버 응답에는 영향이 없습니다 (4절 응답의 `source` 이미지로 원본을 쓸 수 있음).
- `accentArgb`는 서버가 결과 PNG에서 뽑은 대표색입니다. **부호 없는 32비트**(0–4294967295)이므로 앱에서 정수 범위에 주의하세요 (Dart `int`는 문제없음).
- `face`는 생성 PNG의 얼굴 좌표 지도입니다. 생성 직후 한 번만 분석해 저장하며, 실패하거나 좌표 검증을 통과하지 못하면 `null`입니다. `null`이어도 생성은 성공이고 앱은 얼굴 덧그리기만 생략합니다. 형식은 `docs/face-analysis-design.md`를 따릅니다.
- 얼굴 좌표 분석은 OpenRouter의 `openai/gpt-6-luna`와 사용자 검수 예시 6장을 사용합니다(OI-03 부분 결정, 2026-10-09 사용자 확정).

실패 응답:

```json
{"jobId": "9b1d...", "status": "failed",
 "error": {"code": "generation_unavailable", "message": "잠시 후 다시 시도해 주세요.", "retryable": true},
 "createdAt": "...", "updatedAt": "..."}
```

| `error.code` | 의미 | `retryable` |
|---|---|---|
| `generation_rejected` | AI가 입력 이미지로 캐릭터를 만들지 못함·정책 위반 (모델 쪽 거부) | false |
| `invalid_source_image` | AI가 입력 이미지를 읽을 수 없음 | false |
| `generation_timeout` | 서버 작업 시간 초과 | true |
| `generation_unavailable` | 일시적 서버·외부 서비스 장애 | true |

- 모델이 못 만드는 경우(`generation_rejected`)와 서버 장애(`generation_unavailable`)는 코드로 구분됩니다.
- **재시도 방법**: `retryable: true`면 같은 `sourceAssetId`로 **새 `Idempotency-Key`를 붙여 `POST /v1/generations`를 다시** 호출합니다 (새 작업이 만들어짐). 같은 키로 재호출하면 같은(실패한) 작업이 그대로 돌아옵니다. 실패한 작업을 다시 돌리는 별도 API는 없습니다 (FR-04.7).
- `retryable: false`면 같은 원본으로 다시 해도 소용이 없으므로 다른 그림·사진을 올리도록 안내해 주세요.

**취소** `POST /v1/generations/{jobId}/cancel`
- 응답 `200`은 서버가 판단한 **최종 상태**입니다: `{"jobId": "...", "status": "cancelled" | "succeeded" | "failed"}`.
- 취소와 완료가 동시에 일어나면 `succeeded`가 올 수 있습니다. 이때 앱은 **사용자가 취소한 시도의 늦은 결과로 다음 화면에 넘어가지 않아야** 합니다 (FR-04.5). 이미 끝난 작업을 취소해도 오류 없이 현재 최종 상태를 돌려줍니다.
- 앱이 화면을 떠난 것과 서버 작업 취소는 별개입니다. 서버는 `cancel`을 받았을 때만 작업을 취소합니다.
- 취소하면 해당 작업이 만든 결과 파일은 즉시 삭제됩니다 (8절).

**시간 한도**
- 서버 작업 최대 시간은 **4분**입니다. 처리 시작 후 4분이 지나면 `failed`(`generation_timeout`, `retryable: true`)로 끝납니다.
- 앱의 5분 UI 한도와는 별개입니다. 앱의 5분 시간 초과는 서버 실패가 아니므로 같은 `jobId`로 다시 조회할 수 있습니다 (FR-04.6).
- API는 UI 애니메이션 상태와 무관합니다. 빠른 성공도 앱이 연출을 마친 뒤 다음 단계로 넘어가면 되고, 백그라운드에서는 이동하지 않아도 됩니다.

**복구**
- 앱이 종료됐다가 돌아오면 저장해 둔 `jobId`로 최종 상태를 조회합니다. 작업은 **생성 후 24시간** 동안 조회할 수 있고, 이후에는 404입니다.

### 성격 유형 목록
`GET /v1/personality-types` → `{"items": [{"code": "cheerful", "label": "활발하고 씩씩해요"}, ...]}`

초기 목록은 아래 6개입니다. 순서가 곧 화면 표시 순서입니다.

| `code` | `label` |
|---|---|
| `cheerful` | 활발하고 씩씩해요 |
| `gentle` | 다정하고 따뜻해요 |
| `curious` | 호기심이 많아요 |
| `shy` | 수줍음이 많아요 |
| `calm` | 느긋하고 차분해요 |
| `playful` | 장난꾸러기예요 |

- 목록은 **서버가 관리**하므로 문구와 항목이 바뀔 수 있습니다. 앱은 **응답 목록을 그대로 표시**하고 `code`를 하드코딩하지 마세요. 항목이 바뀌어도 이미 만든 친구의 `personalityType`은 그대로이며, 응답의 `personalityLabel`로 표시 문구를 받을 수 있습니다.

### 생성 요청

```json
{
  "generationJobId": "9b1d...",
  "name": "구름이",
  "personalityType": "calm",
  "favoriteThings": ["구름", "사과"],
  "speechStyle": "해요체"
}
```

| 필드 | 규칙 |
|---|---|
| `generationJobId` | 내 작업이고 `succeeded`여야 함. **작업 하나로는 친구 하나만** 만들 수 있음 |
| `name` | 공백 제거 후 **1–12자**. 글자 수는 사용자에게 보이는 글자(grapheme) 기준 |
| `personalityType` | `GET /v1/personality-types`의 `code` 중 하나 |
| `favoriteThings` | **1개 이상** (최대 8개, 중복 불가). 값은 현재 앱의 선택지 8개와 **글자 그대로** 같아야 함: `사과`, `친구랑 놀기`, `산책`, `구름`, `낮잠`, `그림`, `노래`, `바다` |
| `speechStyle` | `~지요!`, `해요체`, `반말` 중 하나 (글자 그대로) |

- 이름·성격·좋아하는 것·말투가 모두 필요합니다. **편집 화면이 없어지므로**(D-24) 요청서가 물은 "성격 빈 값 허용", "성격 최대 30자", "소개문 편집"은 해당이 없습니다.
- 요청서가 말한 "자유 서술형 말투·데모 취향 값"은 **서버로 옮기지 않습니다.** 데모 친구(뭉글이·뚜치·네모린)는 서버 데이터가 아니라서 이관 규칙이 필요 없습니다 (A-08). 선택지 목록(좋아하는 것·말투)을 바꾸면 앱과 서버를 함께 바꿔야 합니다.
- 클라이언트가 보낸 이미지 경로·색상은 쓰지 않습니다. 이미지와 대표색은 서버가 `generationJobId`의 결과에서 가져옵니다 (FR-05.3).

### 응답 (Character)

```json
{
  "id": "5d0e...",
  "name": "구름이",
  "personalityType": "calm",
  "personalityLabel": "느긋하고 차분해요",
  "introduction": "하늘 위에서 놀다 왔어!",
  "favoriteThings": ["구름", "사과"],
  "speechStyle": "해요체",
  "source":    {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/jpeg", "width": 1200, "height": 900},
  "art":       {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png", "width": 1024, "height": 1024},
  "thumbnail": {"assetId": "...", "url": "...", "expiresAt": "...", "contentType": "image/png", "width": 256, "height": 256},
  "accentArgb": 4289974783,
  "face": {"version": 1, "size": [1024, 1024], "facing": "front", "head": [250, 100, 520, 500], "eyes": [[410, 300, 42], [610, 300, 42]], "mouth": [510, 470, 130, 52], "cheeks": [[350, 420, 50], [670, 420, 50]]},
  "createdAt": "2026-10-05T05:01:00Z"
}
```

- 요청서 제안에서 **빠진 필드**: `level`, `memories`, `sleepSchedule`, `isFavorite`, `revision` (모두 범위 밖).
- `source`(업로드 원본)는 **항상 포함**됩니다(서버에서 만든 친구는 항상 값이 있고, 원본이 없는 데이터만 `null`입니다). 집 벽의 그림 등으로 쓰셔도 되고, 안 쓰면 무시하면 됩니다 (요청서가 물은 원본의 용도에 대한 답: 서버는 원본을 친구가 있는 동안 보관하고 화면 사용을 막지 않습니다).
- `introduction`은 저장 직후 서버가 소개 문구(**최대 70자**)를 AI로 만들어 응답에 넣습니다. 서버의 대기 한도는 **10초**이며, **실패하면 친구 저장은 성공하고 `introduction`은 빈 문자열**입니다. 앱은 빈 문자열이면 기본 소개문을 보여 주세요 (FR-05.4). 그래서 `POST /v1/characters`는 **최대 약 10초 이상** 걸릴 수 있으니 앱의 요청 시간 한도는 **20초 이상**으로 잡아 주세요.
- 이미지 URL은 60분 뒤 만료되므로 3.1절의 갱신 방법을 따르세요.
- `face`는 생성 결과와 같은 저장값이며 다시 분석하지 않습니다. 분석 실패 시 `null`이고 친구 저장·조회에는 영향이 없습니다.

### 생성 응답 코드와 오류

| 상황 | 응답 |
|---|---|
| 성공 | `201` + Character |
| 같은 `Idempotency-Key` 재요청 | `200` + 같은 친구 (두 번 만들어지지 않음) |
| 같은 키 재요청이 소개문 생성 중에 도착 | `200` + 그 시점의 친구 (`introduction`이 비어 있을 수 있음. 앱은 빈 문자열이면 기본 소개문을 보여 주면 됨) |
| 작업이 아직 `succeeded`가 아님 | 409 `generation_not_ready` |
| 다른 키로 이미 사용한 작업 | 409 `generation_job_already_used` |
| 남의 작업, 없는 작업 | 404 `not_found` |
| 입력 검증 실패 | 422 `validation_error` + `fieldErrors` (예: `{"name": "string_too_short", "favoriteThings": "too_short"}`) |

### 목록
```json
{"items": [ {Character}, ... ], "nextCursor": null}
```
- **최신순**(만든 시각이 늦은 것이 먼저)입니다. 데모 규모라 한 번에 모두 내려 주고 `nextCursor`는 항상 `null`입니다(나중에 페이지를 나눌 때를 위한 필드입니다). 보유 친구 수는 `GET /v1/me`의 `characterCount`로 받으세요.

### 삭제
- 친구를 지우면 그 친구의 **대화 기록, 원본·캐릭터 아트·썸네일 파일이 함께 삭제**됩니다 (FR-06.3). 되돌릴 수 없으므로 앱의 삭제 전 확인은 유지해 주세요.
- 지운 친구가 **프로필 아바타**였다면 아바타가 기본값(`avatarCharacterId: null`)으로 바뀝니다.
- 과거 주문 스냅샷 보존은 주문 범위 밖(D-22)이라 해당이 없습니다.
- 응답은 `204`입니다. 이미 지웠거나 남의 친구면 404입니다. 삭제가 실패하면 성공으로 응답하지 않습니다.
- 친구 정보를 지우는 데 성공하면 `204`입니다. 저장소의 **파일 삭제가 일시적으로 실패해도** 친구는 이미 지워진 상태이므로 `204`를 응답하고, 남은 파일은 서버가 **1시간 안에 다시 지웁니다** (목록·상세에서는 즉시 사라집니다).

## 5. 프로필 ✅

요청서 경로를 따릅니다: `GET /v1/me`, `PATCH /v1/me`. 찜 API는 ❌입니다.

```json
{
  "nickname": "그린고블린",
  "avatarCharacterId": null,
  "friendNotifications": true,
  "orderNotifications": true,
  "characterCount": 2
}
```

- 처음 로그인하면 서버가 프로필을 만듭니다. 기본 닉네임은 `그린고블린`입니다. 계정 하나가 아이 프로필 하나입니다 (요청 D-01의 답).
- `PATCH`는 보낸 필드만 수정하고(부분 수정), 응답은 수정된 프로필 전체입니다. 수정할 수 있는 필드는 `nickname`, `avatarCharacterId`, `friendNotifications`, `orderNotifications`입니다.
  - `nickname`: 공백을 제거한 값이 **1–12자**. 비어 있으면 422.
  - `avatarCharacterId`: **내 친구의 ID**만 지정할 수 있고, 아니면 422 (`fieldErrors: {"avatarCharacterId": "character_not_found"}`). `null`은 기본 아바타입니다.
- 집계는 `characterCount`(보유 친구 수)만 제공합니다. 친구를 만들거나 지우면 다음 조회에 바로 반영됩니다. 추억 합계는 삭제됐고(D-14), "진행 중 주문 수"는 앱 mock을 그대로 쓰세요(D-22).
- 알림 플래그는 **저장만** 하고 푸시는 보내지 않습니다.

## 6. 친구의 집 ✅

### 6.1 수면 상태
`GET /v1/characters/{id}/status`

```json
{"asleep": false, "nextChangeAt": "2026-10-05T13:00:00Z", "serverTime": "2026-10-05T05:00:00Z"}
```

- 모든 친구가 한국 시간(Asia/Seoul) **22:00–06:00**에 잡니다. 판정은 **서버 시각 기준**이고 `nextChangeAt`은 다음 전환 시각(UTC)입니다.
- 앱은 같은 규칙으로 화면을 미리 바꿀 수 있지만 기준은 서버입니다. 기기 시계가 어긋났을 때 보정할 수 있도록 `serverTime`을 함께 줍니다.
- 자는 동안에는 서버도 대화를 거부합니다 (6.2절). 간식은 앱 안의 모션뿐이므로 서버를 호출하지 않으며, 자는 동안 막는 것은 앱이 합니다.
- 요청서가 물은 **수동 재우기/깨우기와 자동 일정의 충돌, 시간대·여행·기기 시계 변경, 기상 보상 중복 문제는 해당이 없습니다.** 수동 조작, 일정 편집, 상태 수치가 모두 없기 때문입니다 (요청 D-06의 답). 시간대는 항상 한국 시간으로 고정입니다.

### 6.2 대화
요청서는 생성형 대화를 후속 범위로 분리할 수 있다고 했지만, 백엔드는 **이번 범위에 포함**합니다 (D-16).

`POST /v1/characters/{id}/messages`

```json
{"clientMessageId": "client-msg-0001", "text": "오늘 뭐 했어?"}
```

응답 `200`:

```json
{
  "userMessage":      {"id": "...", "role": "user",      "text": "오늘 뭐 했어?", "createdAt": "..."},
  "assistantMessage": {"id": "...", "role": "assistant", "text": "구름 구경했지요!", "source": "ai", "createdAt": "..."}
}
```

- `source`는 답의 출처입니다: `ai`(생성형) 또는 `script`(기존 스크립트 대사로 대체).
- 같은 `clientMessageId`로 다시 보내면 **새로 기록하거나 답을 다시 만들지 않고 이전 결과를 그대로** 돌려줍니다 (중복 전송 방지).
- 입력과 AI 답변을 모두 검열하며, 문제가 있거나 AI 호출이 실패·시간 초과(**15초**)되면 오류가 아니라 **스크립트 대사(`source: "script"`)로 정상 응답**합니다. 앱은 `source`와 상관없이 같은 방식으로 보여 주면 됩니다.
- 친구의 답은 짧은 문장(대략 100자 이내)입니다.

| 상황 | 응답 |
|---|---|
| 자는 시간 | 409 `character_asleep` |
| 빈 메시지, **200자 초과** (공백 제거 후 기준) | 422 `validation_error` (`fieldErrors: {"text": "..."}`) |
| 요청 횟수 초과 | 429 `rate_limited` |
| 남의 친구 | 404 `not_found` |

- 빠른 답 버튼 4종('오늘 뭐 했어?', '뭘 좋아해?', '같이 놀자!', '사랑해!')도 같은 API로 보냅니다.
- 요청서의 `characterProgress`(추억·레벨)와 `status`(기분·친밀도) 응답은 **없습니다.** 대화는 상태·성장·캐릭터 설정에 영향을 주지 않습니다 (D-14, D-17). 그래서 "원자 처리", "보상 중복" 문제도 해당이 없습니다.
- 서버는 AI에게 친구의 설정(이름·성격·좋아하는 것·말투·소개)과 **최근 대화 20개**를 문맥으로 줍니다.

`GET /v1/characters/{id}/messages?limit=30&before=<cursor>`
- 친구의 집에 다시 들어오면 이전 대화를 **최신순**으로 불러옵니다 (FR-09.7). 응답은 `{"items": [{user 또는 assistant 메시지}, ...], "nextCursor": "..." }`입니다. `limit` 기본 30, 최대 100. 더 불러올 것이 없으면 `nextCursor`는 `null`입니다. 다음 페이지는 `before=<nextCursor>`로 요청합니다.
- 대화는 **친구를 삭제할 때까지 서버에 저장**합니다 (요청 D-08의 답). 별도 만료는 없습니다.

## 7. 캐릭터 모션과 얼굴 지도 ✅

- Meta Animated Drawings 기반 GIF 모션 파이프라인과 `GET /v1/characters/{id}/motion`은 만들지 않습니다(D-26).
- Flutter가 캐릭터 PNG 한 장으로 몸 전체 애니메이션을 처리합니다.
- 백엔드는 생성 PNG 직후 얼굴을 한 번 분석하고, 3.3절 생성 성공 응답과 4절 Character 응답의 nullable `face`로 전달합니다.
- 앱은 `face`가 있으면 눈꺼풀·입·볼을 덧그리고, `null`이면 몸 전체 애니메이션만 유지합니다.
- 친구의 집 진입 시 재분석하거나 별도 API를 호출하지 않습니다. 자세한 검증·저장 흐름은 `docs/face-analysis-design.md`를 따릅니다.

## 8. 파일·데이터 보관과 삭제 규칙 ✅

요청서가 요구한 임시 파일 보관 기간, 취소 시 삭제, 이용자 삭제 규칙입니다.

| 대상·상황 | 규칙 |
|---|---|
| 업로드 원본, 생성이 **실패**한 경우 | 재시도를 위해 **24시간 보관**. 같은 `sourceAssetId`로 새 작업을 만들 수 있음 |
| 친구로 저장되지 않은 업로드·생성 결과·작업 기록 | **24시간 뒤 삭제**. 정리는 1시간마다 실행하므로 실제 삭제는 24–25시간 사이 (FR-04.8) |
| 생성 중 **취소** | 해당 작업의 결과 파일은 즉시 삭제. 원본은 재시도할 수 있게 24시간 유지 후 삭제 |
| 친구로 **저장된 후** | 원본·캐릭터 아트·썸네일을 친구와 함께 보관 |
| 친구 **삭제** | 친구, 대화 기록, 원본·아트·썸네일을 즉시 영구 삭제 |
| 작업(`jobId`) 조회 가능 기간 | 생성 후 24시간 |
| `Idempotency-Key` 유지 기간 | 만들어진 작업·친구가 있는 동안 (최소 24시간) |
| 이용자 **삭제/탈퇴** | 앱의 탈퇴 기능은 없음(A-07). 시연이 끝나면 **운영자가** 계정을 삭제하고, 그 사용자의 친구·대화·파일을 함께 삭제 |
| 접근 범위 | 파일·작업·친구·대화 모두 **소유자 본인만** (타인의 ID는 404) |

- 대화 원문, 그림·사진은 일반 서버 로그에 남기지 않습니다. 시연용 계정만 사용하며 실제 아동 데이터는 받지 않습니다 (D-09). 요청서가 말한 파일·메시지·주문 데이터별 보관·삭제는 위 표가 전부입니다(주문 데이터는 범위 밖).

## 11. 인수 기준과 제공 일정

| 요청서의 연속 흐름 | 이번 범위 |
|---|---|
| 1. 사진·그림 → 생성 → 상태 조회 → 결과 조회 → 친구 저장 → 재실행 후 목록·집 조회 | ✅ 포함 |
| 2. 소개문 수정, 찜, 수면 시간 수정 → 행동·대화 보상 → 삭제·복구 정합성 | ❌ 수정·찜·수면 편집·보상·복구 없음. **삭제 시 아바타 기본값 복귀, 연쇄 삭제**와 **대화 중복 전송 방지**는 포함 |
| 3. 견적 → 배송지·동의 → 주문·결제 → 제작/배송 상태 | ❌ 범위 밖 |
| 4. 다른 사용자의 `assetId`, `jobId`, `characterId`로 조회·수정 시 차단 | ✅ 포함 (`addressId`, `orderId`는 범위 밖) |
| 5. 네트워크 실패·중복 클릭·동일 키 재시도·상태 충돌·얼굴 분석 실패 | ✅ 포함. 얼굴 분석 실패 시 생성 성공 + `face: null` |

### 환경과 제공 순서
- **공개 서버(개발·시연 환경)는 아직 배포 계획이 정해지지 않았습니다.** 주소와 일정이 정해지는 대로 알려 드립니다. 개발용과 시연용은 분리해서 운영할 예정입니다. 시연용 계정은 백엔드가 만들어 드립니다.
- 그전에는 **서버를 로컬에서 띄워서** `/docs`(OpenAPI)로 계약을 확인하실 수 있고, 시드 스크립트(`python -m scripts.seed`)로 테스트용 친구를 만들 수 있습니다. 실행 방법은 저장소의 `server/README.md`를 보세요.
- API는 아래 순서로 준비합니다.
  1. **구현 완료**: 서버 상태(`/v1/health`), 프로필(`/v1/me`), 친구 목록·상세·삭제, 수면 상태 (`/v1/characters`, `/v1/characters/{id}/status`)
  2. 업로드 → 생성 → 친구 저장 (`/v1/assets`, `/v1/generations`, `/v1/characters` 생성)
  3. 대화
  4. 얼굴 좌표는 생성 성공·친구 응답에 함께 제공
